### 2.3 新增 AD11:`analysis_vector_to_raster` 失败根因与修复

**根因链**(worker 实跑失败、本地全链模拟成功的差异解释):
1. `{DATA_ROOT}` 占位符**唯一解析点**是 `workflow_definition_service.py:62-71` `_expand_seed_placeholders`(种子同步写运行时文件时展开);`get_definition()` 读运行时文件(已展开),**compile API 保留字面 `{DATA_ROOT}`**。
2. smoke 工具对无专属 patch 的种子走通用 override(`datasource_selection={}`),`build_payload` 中 `ds = overrides.get("datasource_selection")` 得到空 dict → `extract_datasource_selection(defn)` **不执行**(isinstance dict 短路)→ payload 无已解析 input_path。
3. 后端 `_flatten_ui_workflow_definition` 的 `existing_ds={}` → `canvas_ds` 从 compile 图节点提取**字面** `{DATA_ROOT}/_runtime/smoke_vector.geojson` → `Path.exists()=False` → `resolve_geojson` 抛 "Need GeoJSON via port, path, or upstream artifact"。
4. 其余 10 个 analysis 种子在 smoke patch 列表内有专属 datasource 补丁,故成功。

**修复(双侧)**:
- **后端(防御纵深)**:提交边界展开占位符——`_extract_datasource_selection_from_nodes` 中对提取的 path 先做 `{DATA_ROOT}`/`{DATA_ROOT_WIN}` 展开(复用 `_expand_seed_placeholders` 的 settings.data_root 逻辑),再做 is_absolute/exists 判断。
- **smoke 工具**:修通用 override——空 dict 时回落 `extract_datasource_selection(defn)`(与 build_payload 的 isinstance 短路对齐),或在 analysis 分组统一提取。
- worker 状态目录疑点(request_json 未在预期库中)按此根因**不再追查**——失败机制已完整解释,修复后复跑即证。
