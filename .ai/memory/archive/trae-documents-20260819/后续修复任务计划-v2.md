## 修复任务

### P0 — 阻断级

#### P0-1: `runtime_router.py` 双重编码 mojibake 修复

- **文件**: `Code/backend/app/api/routers/runtime_router.py`
- **问题**: 文件存在 UTF-8 BOM（`EF BB BF`），且全部中文注释/docstring 为双重编码 mojibake（原始 UTF-8 被误读为 GBK 再以 UTF-8 重新保存）。例如第 71 行 `杩斿洖鍚庣` 应为 `返回后端进`。文件虽能被 Python 解析，但中文注释完全不可读，严重影响维护。
- **受影响行**: 第 71-73、84、87、102、114、123、134、159、176、201、222、235、248 行等全部含中文的注释。
- **修复方案**:
  1. 用 GBK→UTF-8 重编码恢复原始中文文本
  2. 移除 UTF-8 BOM（与仓库其他 `.py` 文件保持一致）
  3. 顺带修正 P3-2 遗留：第 83、234、247 行 `-> dict:` 改为 `-> dict[str, Any]:`
- **验证**: `CODEBUDDY_SESSION_ID= CLAUDE_SESSION_ID= CODEBUDDY_SAFE_DELETE_SANDBOX= Env/Python312/python.exe -m pytest Test/backend -p no:cacheprovider --basetemp="Test/.pytest-fix" -q -k runtime`

#### P1-3: `useSidebarSearch.ts` deep watch 性能优化

- **文件**: `Code/frontend/src/components/layer-sidebar/useSidebarSearch.ts` 第 88 行
- **问题**: `deep: true` watch 监听 `filteredLibraryByCategory`，在图层库任何嵌套属性变化时触发 `prefetchVisibleWeatherProviders()`，可能造成不必要的天气 provider 网络请求。

- **验证**: `cd Code/frontend && npm run test && npm run build`

## 假设与决策

1. **P0-1 编码修复策略**: 使用 GBK→UTF-8 重编码恢复中文文本，而非手动重写注释。原因：双重编码是可逆的，原文本可完整恢复。同时移除 BOM 以与仓库其他文件一致。
2. **P1-1 类型修复范围**: 仅替换可直接映射到已有契约类型的 `any`。对需要新建复杂接口的（如 `AnalysisChart`），在组件内部定义最小化接口。
3. **P1-2 except Exception 策略**: 不全量收窄，而是分两步：(a) 对有意保留的添加 `# noqa: BLE001` 标注 + 日志；(b) 对能收窄的替换为具体异常类型。已有 `# noqa` 的不修改。
4. **P2-2 console 策略**: 仅对业务关键路径（工作流执行/定义/定时器）接入 `useLogStore`，WebGL 渲染层保持 `console` 不变。
5. **P3 项处理**: TODO 转 issue、测试覆盖和 mypy 警告不在本轮实施，标记为后续迭代。
