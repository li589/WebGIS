# 分析面板样式一致性 + 自动统计 + 工具 UX/主题化 改进计划

> 取证基准：2026-08-18，dev 分支 `1e61f53`。执行阶段使用 `build-web-apps:frontend-testing-debugging` 做浏览器验证、`brooks-lint:brooks-review` 做收尾审查。

## 一、现状与根因（Phase 1 探查结论）

### 问题 1：新图层默认样式与分析面板初始显示不一致 — 根因已定位

导入矢量（含绘制保存的图层）`style` 字段初始为 `undefined`，地图渲染与面板**各自硬编码默认值**，且互相不同：

| 属性 | 地图渲染（`imported-layer-module.ts` L164/L187/L204/L222） | 面板显示（`InfoPanelStyleTab.vue` L205/L220/L236/L251） |
|---|---|---|
| 颜色 | `resolveThemeColor('--success')` | `'var(--accent)'` |
| 线宽 | 2 | 2 |
| 点半径 | 4 | 5 |
| 填充透明度 | 0.25 | 0.35 |

附带缺陷：面板 color 输入 `:value="importedVectorStyle.color || 'var(--accent)'"` 把 CSS 变量字符串传给 `<input type="color">`，本身是无效色值。

其余图层类型已同源，无需处理：目录图层/天气层图例走 `effective-layer-symbology.ts`（侧栏 `useSidebarSymbology.ts` 与面板 `useLayerSymbology.ts` 同源）；导入栅格无就地样式（只读色带提示）。

### 问题 2：自动统计缺失 + 直方图残留

- `ZonalStatsCard.vue`（地图右上浮卡，仅 draw 模式显示）：已有后端栅格统计（`POST /analysis/zonal-stats/sync` → mean/max/min/count/std），但**无测地线面积/周长**，且标题为「区域统计」。
- 全前端无多边形测地线面积/周长代码（无 turf，`measure-geo.ts` 仅 haversine 线段距离）。
- 直方图：分析面板工具卡片**已在此前提交移除**（`Test/backend/test_analysis_panel.py` 断言无 `stats.histogram`）；残留物：① `analysis_run_service.py` L185-188/L394 死分支（catalog 已无此工具，永远不可达）；② workflow 编辑器「直方图统计」节点 + `analysis_histogram.json` 种子（**有意保留**，供编辑器手动编排）；③ 前端 `AnalysisResultCharts.vue` histogram→bar 渲染分支与 ChartType 契约（通用图表能力，非工具入口）。

### 问题 3：工具可用性 + UI 优雅 + 返回按钮 + 多主题

- **「好多工具用不了」的机制**：10 个工具中 8 个（zonal_stats/clip/reclassify/contour/slope_aspect/raster_calc/raster_to_vector/watershed）硬性要求「已导入的静态栅格图层」（前端 `tool-page-model.ts` RASTER_INPUT_TOOLS + 后端 `analysis_run_service.py` fail-closed）。无本地栅格的新用户 8/10 全禁用，天气瓦片层也仅 buffer 可用。算法本身全部真实现（无 stub），**是数据前置条件 + 引导不足，不是 bug**。
- **返回按钮**：`ToolRunPage.vue` L59 / `InfoPanelToolsTab.vue` L276 的 `.page-back` 为 12px 无边框次要色文本链接，极不显眼。
- **ECharts 不随主题**：`AnalysisResultCharts.vue` 未传 theme（ECharts 默认调色板，暗底下对比差）；`MultiLayerTimeSeriesChart.vue` 硬编码 `#9ab`/`#556`；`MultiOverlayBarChart.vue` 回退 `#4fc4f7`。自绘 SVG 的 `PointTimeSeriesChart.vue` 已用 token（正常）。工作流画布已有成熟先例 `canvas-theme.ts`（getComputedStyle 解析 token + 主题切换失效缓存）。

## 二、改动方案

### D1 导入/绘制矢量默认样式统一（问题 1）

**决策：以地图现状为视觉基准**（`--success` 色、radius 4、fillOpacity 0.25、width 2），抽取单一常量真源。

1. `src/stores/layers/imported-vector.ts`：新增并导出 `IMPORTED_VECTOR_STYLE_DEFAULTS`（`color` 为具体 hex 常量 `#3fb27f`——即 `--success` 暗色值，执行时以 `tokens.css` 实际值为准；`width: 2, radius: 4, fillOpacity: 0.25`）；`buildImportedVectorPayload()` 在 style 未指定时填入该默认对象（**创建图层即写实**，不再是 undefined）。
2. `src/components/map/imported-layer-module.ts`：`addVectorLayer`/`applyLayerStyle` 的 `?? 兜底值` 全部改读同一常量（L164 的 `--success` 解析仅作常量来源对照，保留主题解析用于 stroke 等未纳入样式的 paint 项）。
3. `src/components/info-panel/InfoPanelStyleTab.vue`：四个滑条/色块的 `?? 默认值` 改读同一常量；color input 的 fallback 从 `'var(--accent)'` 改为常量 hex。
4. 侧栏图例排查：`useSidebarSymbology.ts` / `LayerSidebarLibrary.vue` 若对导入矢量有独立 swatch 默认值，同步改读常量（探查显示同源，预计无需改，执行时确认）。
5. 新增一致性单测（`Test/frontend/`）：断言面板初值 === 地图 paint 兜底值 === 常量。

### D2 自动统计（问题 2）

**决策：面积/周长自研球面公式**（项目惯例避免 turf，`measure-geo.ts` 已有先例），周长复用 haversine；面积用球面梯形盈余公式 + WGS84 等面积半径 R=6371007.2m，UI 标注「球面测地线近似」，精度 <0.5% 足够展示。

1. 新建 `src/components/map/geometry-stats.ts`：
   - `geodesicAreaM2(geometry: GeoJSON): number`（Polygon/MultiPolygon，外环正、洞负，逐环累加）
   - `geodesicPerimeterM(geometry: GeoJSON): number`（haversine 逐段，复用 `measure-geo.ts`）
   - `formatArea` / `formatLength`（m²↔km²、m↔km 自适应）
   - 单测 `Test/frontend/`（矩形/带洞多边形/经线跨越，用已知值断言）
2. `ZonalStatsCard.vue` 更名「自动统计」：
   - 标题与 aria 标签改「自动统计」
   - 表格上方新增两行几何统计：**测地线面积**、**周长**（前端即算，不依赖栅格）
   - 栅格表格保留全部字段（像元数/最大值/最小值即用户所需 count/max/min，mean/std 顺带展示）
   - 无栅格时不再显示 error 文案，仅显示几何统计 + 提示「导入栅格图层后可统计像元值」
3. 新建 `src/components/info-panel/AutoStatsCard.vue`，挂入 `InfoPanelVisualTab.vue` 顶部：
   - 条件：当前选中图层 `isImported` 且几何含 Polygon/MultiPolygon
   - 显示：面积/周长（前端算）+ 对**可见栅格图层**（`importedRaster || dataState==='catalog'`，与 ZonalStatsCard 同筛选）自动调 `zonal-stats/sync`，展示每栅格像元数/max/min
   - 图层 GeoJSON 来源：`importedVector` payload 中的 features（执行时确认数据结构，`imported-vector.ts`）
   - 竞态防护仿 ZonalStatsCard 的 `statsSeq` 模式
4. 直方图残留清理（范围控制）：
   - 删 `analysis_run_service.py` 中 `stats.histogram` 死分支（L185-188 与 L394 集合项）
   - **不动**：workflow 编辑器节点、`analysis_histogram.json` 种子、前端 histogram→bar 渲染分支与 ChartType 契约（通用图表能力，此前已有意保留）
   - 跑 `Test/backend/test_analysis_panel.py` 确认既有断言不破

### D3 工具 UX + 返回按钮 + ECharts 主题化（问题 3）

1. **返回按钮明显化**：`ToolRunPage.vue` / `InfoPanelToolsTab.vue` 的 `.page-back` 改为按钮化样式（`--surface-2` 背景 + `--border` 边框 + lucide `ArrowLeft` 图标 + 13px `--text-primary`，hover 边框变 accent），两处共用一个 class 定义；顺手排查 `PipelineLauncher.vue` 返回按钮统一风格。
2. **工具禁用引导**（`ToolCatalogGrid.vue` + `tool-page-model.ts`）：
   - 卡片 disabled 态：reason 文案前置小图标、颜色改 `--warning` 系，视觉可辨识
   - reason 命中「需要已导入的静态栅格图层」时，卡片内附「去导入数据」按钮 → `workspace-store` 打开 DataWorkspace（复用 DataImportMenu 的打开路径）
   - 天气瓦片层的「请先导出/导入为静态栅格」reason 同样附引导
3. **ECharts 主题适配**：
   - 新建 `src/components/info-panel/echarts-theme.ts`（仿 `canvas-theme.ts`）：`getComputedStyle` 解析 `--text-primary/--text-secondary/--surface-1/--surface-2/--border/--accent/--accent-2/--chart-*`（若 tokens.css 已有 chart token 则用之，无则补）构建 `{ textStyle, axisLine/Label/splitLine, legend.textStyle, tooltip backgroundColor/borderColor/textStyle, color[] 调色板 }`；导出 `buildEchartsTheme()` 与主题变更响应（watch `themeStore.mode` 失效缓存）
   - `AnalysisResultCharts.vue`：注册主题并传给 vue-echarts（`:theme` 或 init option）
   - `MultiLayerTimeSeriesChart.vue`：`#9ab`/`#556` → token 解析
   - `MultiOverlayBarChart.vue`：`#4fc4f7` 回退 → token
   - 跑 `npm run audit:tokens` 确认无新增硬编码色
4. **不做**（列为后续项，本次不扩）：file-only 工具（contour/raster_to_vector/watershed/buffer）结果 GeoJSON 自动上图（需改后端 outputs 声明与结果映射）；8 个栅格工具对天气瓦片层直通（需后端能力）。

## 三、假设与决策清单

| # | 决策 | 依据 |
|---|---|---|
| 1 | 默认样式数值以地图现状为准（radius 4 / fill 0.25 / `--success`） | 地图是用户已见视觉基准，面板向地图对齐 |
| 2 | 创建图层时 style 即写实（hex），不保留 CSS 变量 | MapLibre paint 不支持 `var()`（现状即 resolveThemeColor 解析）；`<input type="color">` 需 hex |
| 3 | 面积/周长自研球面公式，不引 turf | `measure-geo.ts` 明确「避免引入 turf.js」惯例；精度 <0.5% 满足 UI 展示 |
| 4 | 「自动统计」= ZonalStatsCard 更名扩展 + VisualTab 新卡片双入口 | 用户描述「绘制完成的**或导入的**矢量多边形在分析框的图表应当统计」；ZonalStatsCard 现仅覆盖绘制路径 |
| 5 | 直方图仅清后端死代码；workflow 节点/种子/渲染分支保留 | 分析面板工具卡片早已移除（既有测试断言）；编辑器编排属另一功能域，此前有意保留 |
| 6 | 「工具用不了」做引导优化，不做算法/数据直通 | 探查证实 10 工具全真实现，禁用是栅格前置条件；直通天气层为后端大工程 |
| 7 | 栅格自动统计沿用「所有可见栅格图层」策略 | ZonalStatsCard 现状行为，与用户「如果有栅格图层应当自动统计」一致 |
