## 二、现状分析（探查事实）

### 问题 1：全球图层显示范围错误
- 根因 A（裁剪）：`Tools/export_overlay_assets.py` L55 `_CHINA_BBOX=(73,15,137,59)`，`_reproject_ease_to_wgs84`（L356-434）默认裁剪全部 EASE 层；`_CHINA_BBOX` 在 L357/616/779/795/883/936/988/1032/1097/1141/1187/1511 共 13 处使用；Koppen（原生 0.083° 等经纬）也在 L1511 被裁剪。无 argparse，无法 CLI 覆盖。
- 资产实况：`I:\...\_overlays\smap_aux_{albedo,h,bd,sf,b,cf,igbp,vi_qa}` 与 `smap_aux_koppen` 的 bounds JSON 全为 `[72.90,14.94,137.00,59.04]`（中国），而 `layer_descriptors.json` 声明全球（-180,±85,180）——描述符与资产矛盾，即用户所见“全球图层缩到中国”。`landscape_metrics` 同被裁剪。
- 根因 B（GPCP 假阳性）：`overlay_registry.read_bounds` L1377-1393 把合法全球 bounds `(-180,-90,180,90)` 判为 `bounds_warning`（本意抓 EASE 重投影失败），前端 `overlay-image-module.ts` L713-716 弹“图层坐标可能异常”toast。GPCP 资产本身完好（24 期 PNG+JSON，720×360，bounds 全球正确）。
- 附带发现：旧目录 `aux_albedo/aux_*/fy3b_tbv_ts`（未重投影全球 bounds，地理定位错误）仍在盘上但已不被新 spec 引用；`forest-ratio` 描述符 extent（109.6-117.4）与资产（中国全域）不符；`Tools/audit_overlay_assets.py` 的 `_EXPORT_MAP` 不含 `smap-aux-*` 映射，`--regenerate-missing` 无法重建这些层。

### 问题 2：EASE-Grid 仅支持 6933
- `crs_registry.py` L72-79 仅注册 EPSG:6933（proj4，无 WKT）；`_crs_detector.py` L273-297 仅按“坐标幅值 1e6~1.8e7 + 宽高比 2.0~2.7 + 中心近 0”识别 6933；`grid_presets.py`（在 `app/data_io/services/`）已有 3/9/25/36km 全球预置与 `clamp_projected_bounds_to_crs_domain`（仅 6933 特判）。
- 9km/角点常量硬编码 4 处需同步：导出工具 L296-299、`overlay_registry.py` L241-245、`grid_presets.py` L16-17/L63、前端 `crs-transformer.ts` L26-31。前端注册表镜像在 `crs-registry.ts` L71-80。

### 问题 3：图层名不可选
- `LayerSidebarActive.vue`：图层项 L130 `:draggable="true"` 绑在整个 `<li>`；组头 L87 `draggable="true"`；Menu 图标仅装饰（无事件）。`LayerSidebar.styles.css` L921 `.layer-item{user-select:none}`、L994 `.layer-group-header{user-select:none}`；`.layer-name` 无覆写。

### 问题 4：绘制/导入不上图、导出无守卫
- `imported-layer-module.ts` L126-128：`addVectorLayer` 在 map 未 ready 时 `_ensureMap()` 静默 no-op（无排队）；L128 `loaded.has(id)` 去重导致同 id 新数据被跳过（`updateLayerData` L382 存在但同步链不调用）；L135 空 FeatureCollection 直接 return（不建 source）；source/layer 添加无 try-catch，中途抛错即半成品。`MapCanvas.onMapLoad` L501-513 有补同步，但 map 'load' 未触发/初始化失败时图层永久只存在于侧栏。
- 导出链路（`useImportExport.ts` → `adapters/export.ts:exportLayer` L103-163）无任何“未保存/草稿”检查；绘制内容必须先 `saveDrawLayer` 拿到 `backendLayerId` 才能后端导出，但导出前不校验。
- 保存链路本身（`useDrawSave.ts` L79-144：校验→上传→`addImportedVectorLayer`→丢弃草稿）正常，断点全在渲染侧。

### 问题 9：底图失效无响应

- 后端用户体系：`users.sqlite3` 三表（users/sessions/user_resource_permissions），**无任何偏好/工作区表**；既有按用户 KV 模板可抄：`research_data_settings_repository.py`（key PK+get_json/set_json）。

- 建表惯例：无 alembic，repository `__init__` 幂等 `CREATE TABLE IF NOT EXISTS` + additive ALTER；新表新建 `app/services/xxx_repository.py` + 单例 getter。

## 三、实施方案

### W1（问题 1）：去除中国硬裁剪 + 修全球 bounds 误报 + 资产重生成

1. **`Tools/export_overlay_assets.py` 任务表化与 CLI**
   - 增 argparse：`--tasks <name,...>`（默认全量）、`--extent global|china`（默认 `auto`=按任务表）、`--out-root <path>`、`--dry-run`（仅打印将生成的层与目标 bounds）。
   - 每个导出任务声明 `extent`：smap-aux 8 层、koppen、landscape-metrics → `global`（`clip_bounds=None`，目标分辨率 0.25°，EASE 重投影 Resampling.nearest；Koppen 原生 0.083° 网格直接全量输出、如 PNG 过大（>4320 宽）则最近邻降到 0.25°）；ndvi/biomass-cn 等 9 个中国数据层保持 `china`（0.1° + `_CHINA_BBOX`）。
   - `_reproject_ease_to_wgs84` 签名增 `src_crs="EPSG:6933"`（为 W2 铺路）；`_ease_grid_9k_transform` 泛化为按（crs, resolution）查预置。
   - 输出 bounds 写入逻辑不变（全球 bounds 是合法值）。
2. **`overlay_registry.py::read_bounds`（L1377-1393）**：删除 `_is_global` 告警分支，仅保留越界告警（`w<-180 or e>180 or s<-90 or n>90`）。GPCP 假阳性 toast 随之消失。
3. **`Tools/audit_overlay_assets.py`**：`_EXPORT_MAP` 补 `smap-aux-*` 8 层 + koppen + landscape 映射到 `export_smap_aux_layers` 等，使 `--regenerate-missing` 全覆盖。
4. **描述符修正**（`layer_descriptors.json`）：`landscape-metrics-9km` extent 由中国改全球（重生成后按实际数据有效范围核实）；`forest-ratio` extent 由 (109.6,20.1,117.4,25.6) 改为资产实际（中国全域）；跑 `cd Code/frontend && npm run check:catalog`。
5. **GPCP 诊断步骤**（实施时执行）：`GET /layers` 查 `gpcp-precip-ts` 的 `run_readiness`；浏览器开该层看 overlay PNG 请求是否 200（`gpcp_ts/gpcp_YYYYMM.png`）；若因 `merged_into:"precipitation-static"` 分组折叠导致不可见，在前端目录树展开逻辑中放行。`_GPCP_DIR` 与导出工具路径不一致（两处磁盘均不存在）记录为已知问题，数据就位后统一。
6. **资产重生成**（仓库根，管理员终端）：`Env\Python312\python.exe Tools/export_overlay_assets.py --tasks <global 组>` 后 `python Tools/audit_overlay_assets.py` 核对 complete。旧 `aux_*` 错误资产目录不删（已不被引用，留档）。
7. **测试更新**：`Test/tools/test_ease_reproject_fix.py` 断言由“中国 bounds”改为“全球 bounds + 无中国裁剪 + PNG 尺寸 1440×720 级”。

### W2（问题 2）：EASE-Grid 坐标系扩展

1. **`crs_registry.py`**：新增 `CRSDef`：EPSG:6931（EASE-Grid 2.0 北半球 LAEA）、6932（南半球）、3408（EASE-Grid 1.0 北半球）、3410（1.0 南半球）。**proj4 一律用 `pyproj.CRS.from_epsg(n).to_proj4()` 生成后嵌入，禁止手写**（EASE 1.0 用球体 R=6371228，易错）。label 注明半球与版本。
2. **前端 `crs-registry.ts`** 镜像同步 4 项（与后端逐字符一致）。
3. **`grid_presets.py`**：预置扩展——EASE2 NH/SH 3/9/25/36km、EASE1 NH/SH 25km；行列数与 UL 角点取 NSIDC 官方值（常量旁注释出处 URL）。`clamp_projected_bounds_to_crs_domain` 改为按 CRS 查域表：6933 ±17367530.45/±7314540.83；6931/6932 ±9000000；3408/3410 按 pyproj 域。
4. **`_crs_detector.py::detect_from_bounds`**：在现有 6933 判定（宽高比 2.0-2.7）之前增加分支——幅值同域但 `x_span≈y_span`（比值 0.9-1.1，±9e6 量级）→ 返回 `EPSG:6931`（或南半球中心为负时 6932），`confidence=0.55, needs_user_confirm=True`；EASE1（±1.0e7 量级）几何与 EASE2 难区分，检测统一给低置信候选，用户在确认 UI 中手选 3408/3410（注册表已可选）。`_CONFIRM_THRESHOLD=0.7` 不变。

## 六、风险与回滚

- **资产重生成耗时/体积**：I: 盘 9 层全球重投影 + PNG（每层约 1440×720），单层数分钟内；失败可按任务名单独重跑；旧资产被覆盖前 audit 报告留档。
- **MapLibre image source 全球 ±85° 边缘插值畸变**：接受（与导入栅格预览同链路，高纬轻度畸变可容忍）；精确化走 deferred 的 XYZ 瓦片化。
- **stats.histogram 移除**：种子文件 git 可回滚；工作流画布不受影响。
- **同步 LWW 覆盖**：并发双设备同刻编辑可能丢一方改动（savedAt 新者胜）；单用户场景可接受，deferred CRDT。
- **/health 中间件早退**：仅跳过限流与指标记录，安全头保留；不影响鉴权路径。
- **failover 误切**：阈值 8 错/5s 远高于正常偶发 tile 失败；cooldown 10min 防震荡；手动切源始终可用。
