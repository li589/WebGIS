### 「图层导出无效」根因（已定位）

导出链路只覆盖**导入图层**，工作流结果图层无导出路径：

1. 后端 `export_layer`（`Code/backend/app/data_io/services/export_layer.py:42`）只查 `IMPORTS_DIR / layer_id`，不存在即抛 `图层不存在`。
2. 前端 `exportLayer`（`Code/frontend/src/data-manager/adapters/export.ts:63`）`backendIdOf()` 只取 `importedVector.backendLayerId` / `importedRaster.overlayLayerId`，结果图层两者皆无 → 抛 `该图层无可导出数据`。
3. 右键菜单（`layer-context-menu.ts:127`）仅 `isImported`/`isImportedRaster` 显示导出项；结果图层只有「导出（待图层就绪）」禁用项或无「数据」组。
4. 用户语境：反演产出 SM/VOD/Ω 三图层后右键导出 → 无可用导出 = 「图层导出无效」。

而 overlay registry（`Code/backend/app/services/overlay_registry.py:738` `get_overlay_spec`）已持有结果图层的 `source_path`（GeoTIFF 原文件）/`source_pattern`（时序 `source_{time}.tif`）、`time_list`、`crs`、`overlay_dir` —— 后端补一段 overlay 分支即可打通。

## Proposed Changes

### A. 图层导出修复（核心代码改动）

**A1. 后端：`export_layer.py` 增加 overlay 分支**
- 文件：`Code/backend/app/data_io/services/export_layer.py`
- 位置：`export_layer()` 入口 `IMPORTS_DIR` 未命中后（现抛 `FileNotFoundError` 之前）
- 逻辑：调 `app.services.overlay_registry.get_overlay_spec(layer_id)`；命中则：
  - fmt=tif：`source_path` 存在直接读文件返回（`media_type=application/geotiff`，filename 用 spec label/layer_id）；时序层用 `source_pattern.format(time=t)`（t 取 `time` 参数或 `default_time`/`time_list[-1]`）。
  - fmt=png：返回 `overlay_dir/png_filename`（静态 preview.png）；时序 `preview_{time}.png`。
  - fmt=geojson/csv/mat/nc：抛 `ValueError("overlay 图层仅支持 TIF/PNG 导出")`（不引入栅格转矢量/科学格式的隐式转换）。
  - bbox/output_crs：tif 分支经 GDAL（rasterio）窗口裁剪/重投影（复用现有 `_export_raster` 的 opts 机制，若耦合过重则首版跳过 bbox/crs，文档注明）。
- 错误路径不变：registry 也未命中 → 原 `FileNotFoundError`。

**A2. 后端：`/export/layer` 路由无需改**（`ExportBody.layer_id` 直通，overlay id 即 layer_id）。

**A3. 前端：`export.ts` 支持结果图层**
- 文件：`Code/frontend/src/data-manager/adapters/export.ts`
- `backendIdOf()` 扩展第三来源：结果图层 overlay id（实施第一步先读 `Code/frontend/src/stores/layers/types.ts` 与 `workflow-runner.ts`，确认结果图层 ActiveLayer 上 overlay 标识字段——候选 `jobLayer.overlayId` / `renderHint` 携带 / `catalogId` 即 overlay id；以实际字段为准，不新造字段）。
- `exportLayer()`：fmt 限制为 tif/png 走 overlay 路径，其余格式抛友好错误。

**A4. 前端：右键菜单加结果图层导出项**
- 文件：`Code/frontend/src/components/layer-sidebar/layer-context-menu.ts` + `useSidebarContextMenu.ts`
- `LayerContextMenuInput` 增加 `hasOverlayExport?: boolean`（= 结果图层有 overlay id）；为 true 时 data 组显示 `exportTif` / `exportPng`。
- `useSidebarContextMenu.ts` `contextMenuGroups` 计算 `hasOverlayExport` 并传入。

**A5. 测试**
- 后端：`Test/backend/test_export_layer_overlay.py`（新）——fixture 建 overlay spec（tmp source tif）→ 导出 tif/png 成功、geojson 4xx、不存在 id 404。
- 前端：`Test/frontend/components/layer-sidebar/layer-context-menu` 增补 hasOverlayExport 分支用例。

## Assumptions & Decisions

1. 「图层导出无效」按上述根因理解（结果图层无导出路径）；若浏览器复现发现另有故障（如 imported 导出也坏），以复现事实为准修正方案，但后端 overlay 导出扩展仍保留（用户场景需要导出反演结果）。
2. A1 首版 tif 导出不实现 bbox/output_crs（overlay 原文件直出 + png 预览），除非现有 `_export_raster` 可低成本复用；这是有意收敛范围。
3. FY 三账号密码仅写入后端本地凭据库（加密落盘），不进 git、不进前端、不进日志。
4. NSMC 在线实测受真实服务限额影响，全账号被限时判定为「外部依赖受限」，回退验证 NAS 链路，不算本轮失败。
5. 提交拆分为 1–2 笔（按 diff 归属），每笔均 `git add -A` 全量暂存后单命令提交；不使用 pathspec 提交。
6. 不改动 17 个 skip-worktree 文件（NTFS 保护标记保持）。
