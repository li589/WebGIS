# 图层平台结构化底层框架

日期：2026-08-24  
状态：实施方向基线（本轮已落地统一资产工作流骨架）

## 1. 目标

把图层系统从「目录图层 + 若干特例渲染路径」升级为统一平台，支持四类未来扩展：

1. 新图层接入：只需声明数据源、资产策略、渲染策略、工作流模板。
2. 大数据渲染：大数据源先物化/烘焙，地图只消费版本化资产，不在交互请求中直读大文件。
3. 在线数据拉取显示：在线源先转成版本化资产/时间块，再进入统一图层生命周期。
4. 课题组工作流一键显示：工作流参数模板化，执行完成自动物化产物并一键上图。

## 2. 核心原则

- 图层即资产：每个图层都必须有版本、状态、时间模型和渲染句柄。
- 工作流统一状态：所有执行都用 run 模型表达 accepted/queued/running/succeeded/failed。
- 显示与计算分离：地图渲染只读资产；计算/拉取/烘焙由后台队列完成。
- 大数据不入交互路径：交互 API 不读取 GB 级源文件；大数据必须走烘焙、瓦片、金字塔或 COG。
- 能力驱动 UI：前端不问“这是什么特殊图层”，只读取 capability/lifecycle 并渲染状态。

## 3. 领域模型

```text
LayerDescriptor       图层定义（目录/引擎/工作流模板/渲染提示）
LayerAsset            图层数据资产（PNG/COG/瓦片/时间块/版本）
LayerLifecycle        图层生命周期（资产状态 + run 状态 + 渲染状态 + 时间状态）
WorkflowRun           执行记录（统一状态机、队列、诊断、产物引用）
RenderBinding         地图渲染绑定（source/layer/tile template/paint/symbology）
DataSource            数据源（本地/在线/算法输出/导入）
```

### 3.1 图层状态机

```text
added
  -> checking_asset
  -> fresh | stale | missing
  -> queued
  -> running
  -> ready
  -> updating
  -> ready
  -> failed / removed
```

建议状态枚举：

- asset_state: `missing | stale | fresh | updating | failed`
- workflow_state: `accepted | queued | running | succeeded | failed | cancelled | retry_pending`
- render_state: `hidden | loading | visible | failed`
- timeline_state: `empty | ready | stale | updating | failed`

## 4. 图层分类与工作流分类

### 4.1 图层接入类型

| 类型 | 说明 | 典型图层 | 执行通道 |
|---|---|---|---|
| analysis | 算法/分析工作流 | Ω 反演、课题组算法 | `/workflow-runs` |
| asset | 预烘焙地图资产 | AI、HFP、ERA5、GEBCO | `/overlay-asset-workflows/{layer_id}` |
| weather | 天气引擎视口服务 | 风、温度、降水 | 视口瓦片，不占业务 run |
| online | 在线拉取并物化 | FY、SMAP、门户数据 | download/asset 队列 |
| imported | 用户导入 | GeoJSON/GeoTIFF | ingest/asset 队列 |
| maintenance | 系统维护 | 缓存清理、自愈烘焙 | batch |

### 4.2 工作流分类

| workflow_kind | 含义 | 当前/规划接口 |
|---|---|---|
| analysis | 分析计算 | POST /workflow-runs |
| asset_bake | 资产检查/烘焙 | POST /overlay-asset-workflows/{layer_id} |
| online_sync | 在线拉取/同步 | 规划：POST /layer-assets/{layer_id}/sync |
| ingest | 导入物化 | 导入接口 + asset workflow |
| download | 下载导出 | 独立下载队列 |
| weather_viewport | 天气视口 | 天气瓦片服务 |
| maintenance | 维护自愈 | Celery beat / admin |

## 5. 大数据渲染策略

### 5.1 渲染模式选择

| 数据规模/形态 | 策略 | 地图消费 |
|---|---|---|
| 小型静态 | 预烘焙 PNG + bounds | image source |
| 中大型网格 | Web Mercator 重投影 PNG | image source |
| 多波段/可重着色 | 参数化 preview/tile | styled PNG |
| 巨型 GeoTIFF | 金字塔/瓦片 | XYZ raster tiles |
| 超大数据或在线栅格 | COG / TiTiler 风格服务 | XYZ/COG tiles |
| 矢量大数据 | 后端过滤/聚合/瓦片 | vector tiles |

### 5.2 大数据硬规则

1. 交互请求只读资产，不读大源。
2. 大数据源必须进入资产工作流；运行中可先显示旧资产。
3. 更新完成必须 bump `bake_version`，前端按版本刷新。
4. 时间序列资产必须暴露 time_list/default_time/current_time。
5. 渲染几何必须由元数据显式声明，不靠宽高启发式长期兜底。

## 6. 在线数据拉取显示

### 6.1 标准流程

```text
online source definition
  -> sync job/run
  -> source snapshot/version
  -> bake overlay asset
  -> asset version bump
  -> map refresh
  -> timeline blocks update
```

### 6.2 在线源状态

- source_state: `offline | stale | syncing | fresh | failed`
- asset_state 与 source_state 分开：在线源可能 fresh，但资产仍 stale。
- 在线拉取失败时保留旧资产显示，并标记 warning，不清空地图。

## 7. 课题组工作流一键显示

### 7.1 工作流模板

课题组工作流必须声明：

```json
{
  "workflow_template_id": "lab.omega.local",
  "display_name": "Omega 本地反演",
  "engine": "python_provider",
  "inputs": ["region", "time_range", "method"],
  "outputs": ["map_layer", "series", "report"],
  "resource_profile": "heavy",
  "auto_display": true
}
```

### 7.2 一键显示契约

1. 前端提交 workflow run。
2. run 完成产生 `result_refs`。
3. `materialize-map-layers` 把产物注册成 overlay/imported asset。
4. 图层管理器自动添加/替换对应图层。
5. 时间轴从 result metadata 读取 time_list/default_time。
6. 一键重跑时取消旧 run，但保留旧资产直到新资产就绪。

## 8. 接口规划

### 8.1 已有核心接口

- `POST /workflow-runs`：分析/算法/GEE 工作流
- `GET /workflow-runs`：run 列表/恢复
- `GET /workflow-runs/{run_id}`：run 状态
- `POST /workflow-runs/{run_id}/cancel`：取消
- `POST /workflow-runs/{run_id}/retry`：重试
- `POST /workflow-runs/{run_id}/materialize-map-layers`：产物上图
- `POST /overlay-asset-workflows/{layer_id}`：资产检查/烘焙工作流

### 8.2 建议新增接口

- `GET /layer-assets/{layer_id}`：资产当前状态
- `POST /layer-assets/{layer_id}/sync`：在线源同步
- `POST /layer-assets/{layer_id}/rebake`：强制重烘
- `GET /layers/{layer_id}/lifecycle`：聚合生命周期
- `GET /layers/{layer_id}/render-descriptor`：地图渲染描述
- `GET /workflows/templates`：课题组工作流模板列表
- `POST /workflows/templates/{id}/runs`：模板一键执行

## 9. 前端结构化模块

```text
stores/layers/
├─ catalog-runtime        目录、引擎、能力
├─ active-layers          图层集合/删除/显隐
├─ lifecycle              生命周期聚合状态
├─ asset-manager          资产检查/烘焙/在线同步
├─ workflow-runner        提交/轮询/取消/恢复
├─ timeline               时间块/版本/状态
└─ render-sync            地图渲染同步
```

### 9.1 前端统一服务

```ts
interface LayerLifecycleService {
  add(catalogId: string): Promise<void>
  remove(instanceId: string): Promise<void>
  refresh(instanceId: string): Promise<void>
  cancel(instanceId: string): Promise<void>
  setTime(instanceId: string, time: string): Promise<void>
  setVisibility(instanceId: string, visible: boolean): Promise<void>
}
```

UI 只显示统一状态：已添加、资产检查中、排队中、更新中、就绪、失败。

## 10. 当前系统映射

### 已具备

- 统一 run 模型：accepted/queued/running/succeeded/failed。
- 静态资产工作流：`/overlay-asset-workflows/{layer_id}`。
- 资产版本：`bake_version`。
- 大数据保护：GEBCO 不进入交互直读，走后台烘焙。
- 地图渲染：image source、XYZ tile、时间序列 PNG。
- 删除运行中图层：取消 run + dismissed runId 防回弹。

### 待补强

1. workflow_kind 显式写入 run（analysis/asset_bake/online_sync/...）。
2. `/layer-assets/{layer_id}` 资产独立查询接口。
3. `/layers/{layer_id}/lifecycle` 聚合接口，前端不再拼状态。
4. 渲染几何元数据显式化，逐步替代 `isMercatorLinearPng` 启发式。
5. 时间轴读取 lifecycle，显示 stale/updating 状态。
6. 在线源接入统一为 sync job + asset workflow。

## 11. 短期实施清单

优先级 P0：

1. run 模型增加 `workflow_kind` 字段（或 executor_metadata 强制白名单）。
2. 增加 `GET /layer-assets/{layer_id}`。
3. 增加 `GET /layers/{layer_id}/lifecycle`。
4. 前端 lifecycle store 聚合 run + asset + render + timeline。
5. 时间轴显示 fresh/stale/updating。

优先级 P1：

1. 在线源 sync job 标准模板。
2. 课题组工作流模板注册表。
3. render descriptor 接口，前端渲染不再猜。
4. COG/瓦片服务接入大数据新图层。

## 12. 验收标准

- 添加任何图层后，用户能明确看到：资产检查中/排队/更新/就绪。
- 大数据图层添加不会阻塞交互 API，不会导致登出/超时。
- 陈旧资产先显示旧版，同时后台更新，完成后无闪烁刷新。
- 在线拉取失败保留旧资产并提示 warning。
- 课题组工作流完成后自动上图，时间轴同步可用时间块。
- 新图层接入只改配置/模板，不改地图同步主流程。
