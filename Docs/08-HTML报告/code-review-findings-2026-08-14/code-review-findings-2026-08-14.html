test_business_regression.py 静默测试失败
Test/backend/test_business_regression.py
回归测试使用自定义 check() 函数收集断言结果，但 从不主动抛出失败。pytest 视所有测试函数为通过，即使 check 条件为 False。这意味着关键业务回归验证形同虚设——所有回归错误都被静默吞没。
# 问题代码：check() 仅 append 到列表，不触发 assert _results: list[tuple[str, bool, str]] = [] def check(condition: bool, msg: str): _results.append((inspect.stack()[1].function, condition, msg)) # ← 缺少 assert condition, msg def test_regression_case1(): check(result == expected, "Value mismatch in case 1") # 测试始终 "通过"，即使 condition=False
测试可靠性 回归保护缺失
修复方案：将 check() 改为 assert condition, msg，或在函数末尾添加 assert all(r[1] for r in _results) 汇总断言。同时审查 test_open_meteo_performance.py 是否有相同模式。

P1-2
GEE Context 全局锁造成并发瓶颈
app/gee/core/src/webgis_gee/gee/context.py
GeeContext 使用类级 RLock，序列化了所有 GEE 账号的初始化操作。锁在 initialize() 中获取后不释放，一直持有到 close()。这意味着账号池中的账号无法并行初始化，且一个账号的初始化会阻塞其他账号的所有操作。
class GeeContext: _runtime_lock = RLock() # 类级，所有实例共享 def initialize(self) -> None: self._runtime_lock.acquire() self._lock_acquired = True try: self._ee.Initialize(credentials=..., project=...) self._initialized = True finally: # 锁不释放！持有到 close() pass
并发瓶颈 账号池利用率低
修复方案：将锁改为实例级（self._lock = RLock()），仅在 ee.Initialize() 调用期间持有，初始化完成后立即释放。ee.Initialize 本身是线程安全的，不需要跨账号互斥。
