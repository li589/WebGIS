📐 维度 A：架构边界 2 P0 5 P1

A-01 overlay_registry.py 硬编码开发机器绝对路径 P0

症状：Provider Root 路径硬编码为开发机器绝对路径

源：app/services/overlay_registry.py:29-30

_PROVIDER_ROOT = Path(r"d:\temp_desktop\Proj\Comprehensive Geographic Data Analysis system\Code\algorithms\providers\Python")

后果：其他任何环境（CI、生产、其他开发者机器）都无法加载 overlay 注册表，导致图层系统完全不可用

修复：替换为 settings.python_provider_root 或 Path(__file__).resolve().parents[N] 相对路径计算
参考：《A Philosophy of Software Design》第13章「浅模块」· Ousterhout
A-02 weather_sync_service.py 服务层反向导入路由层 P0

症状：Service 层直接导入 Router 层函数

源：app/services/weather_sync_service.py:172

from app.api.routers.weather_router import invalidate_weather_coverage_cache

后果：依赖方向违反（Service → Router），破坏分层架构。Router 变更会波及 Service，且无法独立测试 Service 层

修复：将 invalidate_weather_coverage_cache 移至 Service 层或独立的 cache-invalidation 模块，Router 调用 Service 而非反向
参考：《Clean Architecture》第22章「边界」· Martin
A-03 weather-tile-manager.ts 14 职责 God Store（1948 行） P1

症状：单一 Store 承担 14 项独立职责，6 个模块级可变全局状态

源：stores/weather-tile-manager.ts（1948 行）

职责包括：瓦片缓存管理、全局并发槽位控制、四级优先级队列调度、视口瓦片排序、多图层 round-robin、Generation 代际取消、Gap sweep 补洞、错误分类与退避重试、Soft requeue 断路器、Data version 合并去抖、Zoom-out 过渡加速、Data-empty 422 短路、Merge cache 管理、天气工作流六态映射

后果：测试隔离问题（需 __testResetWeatherTileManagerModuleState() 补丁）、手动响应式模式脆弱（dataVersion/statusVersion/activityVersion 递增可能遗漏 bump）

修复：按职责拆分为 tile-cache.ts / tile-concurrency.ts / tile-scheduler.ts / tile-error-handler.ts 子模块
参考：《A Philosophy of Software Design》第9章「深模块」· Ousterhout
A-04 overlay_registry.py 非线程安全注册表 + import 时注册 17 个 overlay P1

症状：模块级 _REGISTRY dict 无锁保护，17 个 register_overlay() 调用在 import 时执行

源：app/services/overlay_registry.py（行 625-997，分散注册）

后果：并发请求下注册表竞态；所有 overlay 在模块加载时即注册（启动延迟）；跨进程（Celery worker ↔ FastAPI）一致性无保证

修复：使用 threading.Lock 保护注册表操作；改为延迟注册（首次查询时注册）；跨进程一致性通过 Redis 或共享文件实现
A-05 workflow_request_resolver.py 三处 lru_cache 无失效机制 P1

症状：3 处 @lru_cache 缓存文件系统读取结果，无失效/刷新机制

源：app/services/workflow_request_resolver.py:188,1031,1115

_load_module_template_map()（maxsize=1）、_resolve_provider_dataset_path()（maxsize=128）、_load_provider_dataset_helpers()（maxsize=1）

后果：模板文件或 dataset 路径变更后缓存陈旧，需重启 FastAPI 进程才生效（project_memory 已记录此问题）

修复：添加 cache_clear() 暴露为 admin API 端点；或使用带 TTL 的缓存替代 lru_cache
A-06 weather_render_service.py 6 个 build_X_geojson_from_grid 方法代码重复 P1

症状：dewpoint/humidity/pressure/visibility/precipitation/temperature 6 个方法结构几乎完全一致

源：app/weatherengine/weather_render_service.py（行 1054-1455）

后果：已有通用方法 build_scalar_geojson_from_grid（行 1455），但特化方法未被替换/删除——维护时需同步修改 7 处

修复：删除 6 个特化方法，统一调用 build_scalar_geojson_from_grid，仅 wind 方法因外推逻辑保留
参考：《The Pragmatic Programmer》DRY 原则 · Hunt & Thomas

A-10 node_template_registry.py 3398 行数据巨石模块 P2
