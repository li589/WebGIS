## 二、问题清单

### P0（随本报告已修复并带回归锁）

**P0-1 `resolve_palette_id` 运算符优先级 bug——别名机制从未生效。**
`key = aliased or raw.lower() if raw.lower() in _PALETTES else raw` 实际解析为
`(aliased or raw.lower()) if (raw.lower() in _PALETTES) else raw`——凡「原名不是实现键」的别名（`elevation-terrain-ramp`/`spectral-ramp` 等全部）一律回落 viridis。
**已修**：显式 if/else + 补全 17 个缺失映射（descriptor 语义 ramp 13 个 + matplotlib 经典名 6 个），映射目标对齐 overlay_registry de-facto 显示配色。回归：`Test/backend/test_palette_alias_resolution.py` 27 用例。

### P1（高价值，建议尽快）

**P1-A palette 双写漂移：descriptor 语义名 vs registry 实现名，9 处不一致。**
`layer_descriptors.json` 用语义名（`hfp-ramp`/`forest-ramp`/`soil-moisture-ramp`…），`overlay_registry.py` 用实现名（`hot`/`igbp`/`magenta-yellow`…）。同层的 palette 两处维护必然漂移；产物注册取 descriptor 名、静态注册取 registry 名——两侧解析结果不同时即「静态↔产物换源变色」（今日三联报障的深层结构根因）。
**方向**：overlay 注册数据化后以 descriptor.style.palette 为**单一真源**，registry 侧不再写 palette（见 P1-B）；语义 ramp 要么给出独立色带定义、要么 descriptor 直接引用实现键+语义名做别名（本次 P0 已把别名补齐作过渡）。

**P1-B overlay_registry 28 处硬编码注册 → 数据化到 `catalog_seeds/overlay_assets.json`。**
每个 `register_overlay()` 调用即一行配置（layer_id/overlay_dir/png/bounds/palette/vmin/vmax/unit/opacity/source_path/source_reader/source_variable）。抽 `register_overlays_from_config(path)` 循环注册；registry 代码只保留动态导入（imports 目录扫描）与特殊分支（OMEGA label 归一化等少数）。收益：加图层零代码、palette/vmin 改配置即生效、消除 P1-A 双写。
**注意**：source_path 含盘符绝对路径，须与既有 `_data_join` 根派生方式一致（相对 DATA_ROOT）。

**P1-C 44/61 工作流种子缺 `extra.group_title/output_labels`。**
analysis_*/omega_*/下载/统计类种子无中文命名配置 → 组名/成员名走 `productTagLabel`/技术名兜底（今日组名报障只修了优先级，配置面仍未补齐）。
**方向**：批量为 44 个种子补 `group_title`（含 `output_labels` 单产物语义）；纯文件产物（下载类）至少补 group_title 供产物组命名。

### P2（结构改善，择机）

**P2-A OMEGA 硬编码特判 37 处散落 6 个文件（含 generated.json）。**
`run-layers.ts` 30 处（`reconcileOmegaBlockLayers`/游离层并入/占位改名）、`result-adapter.ts` `normalizeProductTag` 5 个 OMEGA 分支、`workflow-runner.ts` LEGACY 三件套。OMEGA 是"productTag 元数据可表达"的普通产品（归并规则 OMEGA_BLOCK/OMEGA_PIXEL→OMEGA），却以 if 分支形式固化。
**方向**：productTag 元数据表化（归并规则/标签/描述/占位名进配置），`normalizeProductTag` 查表归并；`reconcileOmegaBlockLayers` 泛化为"游离去重并入组"通用函数。

**P2-B LEGACY 兼容残留（SM/VOD/OMEGA 三件套）。**
`LEGACY_RESTORE_TAGS`/`LEGACY_PRODUCT_TAG_LABELS` 仅服务旧实验室 run 恢复。注释已有"提交路径禁止落 LEGACY"约束（2026-08-23）。
**方向**：设定退役观察期（如一个月无旧快照回归），随后删除恢复兜底分支，收敛 `run-layers.ts` 约 60 行。

**P2-C 命名清洗函数 3 处重复实现。**
前端 `run-layers.ts cleanTitle`（剥 Algorithm 前缀+路径段+扩展名）、`workflow-expected-outputs.ts stripDataExtension`、后端 `python_provider_result_builder._resolve_product_display_label` 内嵌正则。三处正则各自维护（今日三联报障 A 逐处打补丁即此代价）。
**方向**：前端抽 `utils/layer-naming.ts` 统一 `cleanProductDisplayName()`；后端正则与前端扩展名清单以注释互指（跨语言无法共享代码，但清单可放进共享 JSON——与 P1-B 配置同文件）。

**P2-D descriptor 查找重复 6 处（python_provider_result_builder）。**
`get_layer_descriptor` try/except 块在 generic/science-mat 等分支重复。今日已抽 `_resolve_product_display_label`；palette 查找仍是独立 try/except。
**方向**：抽 `lookup_layer_style(raw_layer_id) -> LayerStyleHint | None` 单一 helper，两分支共用。

**P2-E 前后端色带双维护（24 vs 15+2）——今日两起配色 bug 的结构性根因。**
后端 `_PALETTES` 是渲染真源；前端 `WEATHER_PALETTES` 供选择器/图例。集合不等（后端多 brg/cividis/plasma/hot/terrain 等 10 条）+ 各自兜底（后端→viridis、前端→thermal-orange）造成显示/渲染脱钩。
**方向**：**单源生成**——后端 JSON（`catalog_seeds/palettes.json`，含 label/type/别名）为真源，构建脚本生成前端 `weather-palettes.generated.ts`（含中文 label 与类型），CI 校验两边一致。别名表（本次 P0 已补全）随该文件下发到前端，替换前端 `PALETTE_ALIASES` 手工副本。

### P3（低风险清理）

- **P3-A** `api-config.ts`（1093 行）底图 provider 配置 JSON 化（key 管理仍走 settings，仅 provider/endpoint/style 入 JSON）。
- **P3-B** `resolveRestoreWorkflowBridge` 调用方 `bridge.title` 死分支（该函数从不返回 title）——今日组名修复时已顺手移除两处，剩余一处随 P2-A 清理。
- **P3-C** `catalog-seeds.generated.json` 的再生成入口/时机文档化（当前仅测试 `workflow_seed_sync` 隐式保障）。
- **P3-D** 前端 legend 对未知 palette 的兜底显示（thermal-orange）改为后端下发 palette 元数据后按真源渲染。

## 三、通用基础模块设计（供 P1/P2 落地时参照）

1. **图层登记单源 schema**（`catalog_seeds/`）：
   - `layer_descriptors.json`：目录语义（已有）
   - `overlay_assets.json`（新，P1-B）：烘焙资产/源数据/渲染参数——palette 只在此处出现一次，descriptor.style.palette 引用同值（校验脚本保证一致或直接删一侧）
   - `palettes.json`（新，P2-E）：色带定义+别名+中文 label 单源
   - `product_tags.json`（新，P2-A）：productTag 归并规则/标签/占位名
2. **命名服务收敛**：显示名解析统一入口（前端 `utils/layer-naming.ts` + 后端 `layer_display_names.py`），扩展名/前缀清洗清单进共享 JSON；任何新产物类型只改配置。
3. **配置校验进 CI**：seed↔descriptor↔overlay 三方一致性检查（layer_id 引用存在性、palette 可解析性、group_title 覆盖率）作为 pre-commit/CI 门。

## 五、结论

登记/加载链路**主干已是配置驱动**（descriptor/seed/runtime catalog 下发），但三个关键点仍是代码或双写：overlay 注册（28 处硬编码）、色带（前后端双维护+别名机制失效）、命名（44 种子缺配置+特判散落）。本次已修复其中唯一线上 bug（P0 别名优先级）；P1-B/P2-E 是消除"同层换源变色"类故障的根治项，建议作为下一期重构主线。
