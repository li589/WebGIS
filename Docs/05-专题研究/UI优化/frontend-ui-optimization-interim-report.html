1现状总览

设计系统底座已建立，但业务层迁移严重滞后

CGDA 前端已建立了较为完整的设计 Token 体系（tokens.css）和 9 个基础组件（src/components/ui/），双主题支持完善。但大量业务组件（ModeToolbar、LayerSidebar、InfoPanel、Settings、Workflow 等）仍使用硬编码颜色和手写样式，组件体系、响应式策略、信息架构均未达到设计系统规范要求。

✅ 做得好的方面

  • 设计 Token 体系完整（颜色/间距/字号/动效/层级）
  • 双主题支持完善（暗色 + 浅色，CSS 变量切换）
  • 9 个基础组件质量较高（AppButton/Card/Tabs 等）
  • 地图交互能力强（天气瓦片/风场/标量场）
  • 面板系统功能完善（拖动/缩放/折叠/持久化）
  • 登录页视觉升级已完成

⚠ 主要问题

  • Token 迁移不彻底（1328+ 硬编码颜色）
  • 组件体系不统一（6 种按钮、4 种面板壳）
  • 两套面板并存（ControlPanel vs PanelDock）
  • 响应式断点不统一，移动端适配粗糙
  • LiteGraph 风格与设计系统脱节
  • 图标混用（Lucide SVG / 手写 SVG / Emoji）

2问题详细分析

2.1 Token 迁移不彻底

组件/目录硬编码颜色数严重程度说明
InfoPanel.vue~309 处P0右侧分析面板，完全未 token 化
LayerSidebar.vue~214 处P0左侧图层面板，完全未 token 化
ControlPanel.vue~34 处P1面板容器，核心组件未使用 token
ModeToolbar.vue~10 处P1顶栏部分 token 化，仍有残留
settings/ 目录大量P1设置各子页面普遍未使用 token
BasePanel.vue~8 处P2底层面板壳，完全硬编码

注：硬编码颜色含 hex、rgba、rgb 三种形式，统计自 components 目录下 30+ 个文件

2.2 组件体系混乱

按钮实现（6 种）

  • AppButton — 设计系统级
  • IconButton — 设计系统级
  • .tool-btn — ModeToolbar 手写
  • .mode-btn — 顶栏模式组
  • .tool-button — ControlPanel 工具按钮
  • .icon-button — ControlPanel 图标按钮

面板容器（4 种）

  • BasePanel — 底层玻璃态壳
  • ControlPanel — 可拖动缩放面板
  • PanelDock — 新设计系统面板
  • Card — 卡片容器

2.3 工作流编辑器孤岛

LiteGraph 是 UI 风格割裂的重灾区。节点样式、连线颜色、右键菜单、对话框等都是 LiteGraph 默认风格的微调，与 CGDA 整体深空蓝青主题不统一。

  • 节点属性编辑使用原生输入框 + 手搓 ParamField，与 TextField 不是一套
  • 侧栏拖拽手柄样式独立，与 ControlPanel resize handle 风格不同
  • 滚动条样式独立（.wf-scroll），颜色值与面板滚动条不一致
  • 覆盖样式使用了 20+ 个 !important

2.4 响应式与移动端

问题现状影响
断点不统一Token 定义 640/768/1024/1280，但实际使用 820/900/1100 等响应式行为不可预测
移动端适配少仅 Dashboard 有 3 档 media query设置、工作流等在小屏无法使用
面板无折叠策略小屏转流式布局，但仍占大量空间地图可视区域被压缩
触控目标部分按钮 < 36px触屏操作困难

2.5 Dashboard 过度臃肿

DashboardView.vue 约 1600+ 行，混合了：

  • 时间轴状态协调逻辑
  • 工作流运行状态监听
  • 点查交互逻辑
  • 拖拽导入处理
  • 面板显隐控制
  • 设置面板打开状态

本质上是一个「UI 协调器」，状态桥接逻辑应抽离为 composable 或 store。

4优化路线图建议

结合设计系统规范（S1-S4 路线）与当前实际状态，建议按以下优先级分阶段推进：

第一阶段 · 已完成
基础底座建设
设计 Token 体系 + 基础组件 + 双主题 + 登录页/日志/截图等高频 UI 升级
第二阶段 · 建议优先
顶栏收敛 & Token 迁移（P1）
ModeToolbar 重构为使用 AppButton/IconButton/Chip/Tabs 组件；替换内联颜色为语义 token；emoji 图标统一为 SVG；统一字号到 ≥12px floor
第三阶段 · 核心迁移
面板体系统一 & 业务组件 Token 化（P1-P2）
ControlPanel + BasePanel 迁移到 PanelDock 设计系统；LayerSidebar 和 InfoPanel 卡片化改造 + Token 迁移；Dashboard 状态逻辑抽离
第四阶段 · 体验提升
响应式 & 工作流 UI & 信息架构（P2-P3）
统一响应式断点 + slim rail + bottom sheet；LiteGraph 样式深度定制；TimelineScrubber 语义化；命令面板 Cmd-K；无障碍 WCAG AA 达标

5本波优化具体建议

🎯 聚焦原则

本波优化建议聚焦「见效快、影响面广、风险可控」的改进点，优先选择用户高频接触、改动量适中、可独立验证的项。

# 优化项 优先级 预估工作量 影响范围
1 ModeToolbar 顶栏重构：复用 AppButton/IconButton/Chip，替换 emoji→SVG，Token 化 P0 1-2 天 全局入口视觉统一
2 PanelDock 功能补全：补齐拖动/缩放/持久化，逐步替代 ControlPanel P0 2-3 天 面板系统统一路线
3 LayerSidebar Token 迁移：颜色/字号/间距全面走 token，214 处硬编码清理 P1 1-2 天 左侧图层面板视觉一致性
4 InfoPanel Token 迁移：309 处硬编码清理，卡片化重构 P1 2-3 天 右侧分析面板视觉一致性
5 字号统一到 12px floor：排查并修复所有 <12px 字号 P1 0.5 天 可读性基线
6 Select 组件建设：替换原生 select + 手搓下拉 P1 1 天 表单控件一致性
7 响应式断点统一：所有媒体查询对齐 token 断点值 P2 0.5 天 响应式行为可预测
8 Dashboard 瘦身：抽离时间轴协调/点查/拖拽为 composables P2 1-2 天 代码可维护性
9 工作流编辑器样式初步统一：滚动条/按钮/输入框对齐设计系统 P2 1-2 天 LiteGraph 视觉融合
10 TimelineScrubber 语义化：Token 迁移 + 组件拆分 P3 1 天 时间轴视觉一致性
