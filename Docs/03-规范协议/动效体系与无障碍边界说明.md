# 动效体系与无障碍边界规范

## 一、设计目标与原则

CGDA（综合地理数据分析系统）面向科研院所与专业课题组，承载大范围遥感视口、多维时空瓦片和复杂计算工作流。系统动效遵循以下核心原则：

1. **科研效能优先（Utility First）**：动效是状态传达与时空连续性的辅助手段，严禁纯装饰性干扰；
2. **克制物理阻尼（Calibrated Springs）**：基于 Apple HIG 与自然物理弹性，微反馈严控在 150ms~400ms，杜绝夸张抖动；
3. **无障碍深度防御（Accessibility-First）**：严密界定「减少动效」边界，杜绝前庭综合征（眩晕/恶心），同时保留关键状态传达防假死。

---

## 二、「减少动效（Reduce Motion）」权威边界定义

当用户在「设置 → 外观 → 动效偏好」勾选「减少动效」，或系统底层开启 `prefers-reduced-motion: reduce` 时，系统严格按以下**禁用边界**与**保留边界**执行：

### 1. 禁用与瞬时化边界（Disabling / Instant Switching）——防前庭综合征

以下交互在大跨度位移、频繁晃动或连续视差下最易引发视神经疲劳与眩晕，**必须瞬时化或直接切断**：

| 领域                   | 默认模式                                       | 减少动效模式（Reduce Motion）              | 技术落实点                                                        |
| ---------------------- | ---------------------------------------------- | ------------------------------------------ | ----------------------------------------------------------------- |
| **地理空间跨度运镜**   | 1000ms~1500ms 大跨度弧线运镜（`curve: 1.42`）  | **0ms 瞬时直达（duration: 0）**            | `MapCanvas.vue` / `DashboardView.vue` `isReducedMotionActive()`   |
| **视图跨路由过渡**     | 原生 `View Transitions API` 交叉淡入与模糊过渡 | **跳过过渡动画（瞬时切换）**               | `router.ts` `shouldAnimateViewTransition` 条件门禁                |
| **列表瀑布流交错入场** | 卡片按 `min(i, 8) * 20ms` 阶梯滑入             | **瞬时全量展示（animation: none）**        | `motion.css` `html.reduce-motion .cgda-stagger-item`              |
| **弹窗与抽屉物理位移** | 面板带有 8px~28px 的位移滑动                   | **原地瞬时显隐（translate: 0, scale: 1）** | `motion.css` `html.reduce-motion` 变量压至 0ms                    |
| **状态抖动与弹簧微弹** | 失败 3px 横向微震 / 成功弹性微弹               | **完全消除微震与形变（transform: none）**  | `motion.css` `html.reduce-motion .cgda-node-error`                |
| **时空数据就绪波纹**   | 瓦片就绪时 1.6s 微光光环扩散                   | **隐藏光环扩散（display: none）**          | `motion.css` `html.reduce-motion .cgda-readiness-wave::after`     |
| **深空天体自旋微动**   | 太阳系背景天体 12fps 周期性重绘                | **暂停自动重绘，仅随视角/时间轴更新**      | `GlobeSolarSystemBackdrop.vue` `resolveReducedMotionPreference()` |

### 2. 状态保留与去位移边界（Preserved Feedback）——防止认知假死

为防止用户在进行耗时操作时误判界面死锁，以下场景**必须保留基础状态指示**，但移除多余动态修饰：

| 领域                     | 减少动效模式处理策略                                        | 规避的风险                               |
| ------------------------ | ----------------------------------------------------------- | ---------------------------------------- |
| **算法/工作流进度推进**  | 去除流动 Shimmer 扫光，**保留进度条真实百分比宽度物理推进** | 避免科研人员误以为计算任务已被挂起或终止 |
| **加载旋转指示器**       | 降速为低频旋转（降低 50%~75% 视觉转速）或保留明确文本指示   | 明确传达后台网络/数据仍在同步中          |
| **控件交互与选定状态**   | 保留极简的背景色、边框色、圆点色瞬变（0~50ms）              | 保持点击、选中、聚焦的明确无障碍感知     |
| **图层切换与图层可见性** | 保持即时图层切换与渲染                                      | 确保地图工具箱即时响应                   |

## 三、显存与性能守卫机制

1. **后台 Tab 挂起（Page Visibility API）**：
   - 粒子系统（风场/流线）、3D 深空背景在 `document.visibilityState === 'hidden'` 时自动挂起 `requestAnimationFrame` 循环；
   - 切回前台 `document.visibilityState === 'visible'` 时恢复渲染并清空积压时间戳（避免时间跳变）。
2. **`will-change` 显存分层治理**：
   - 严禁在全屏静态图层上常驻 `will-change: opacity`，避免创建过多的 Composited Layer 显存开销；
   - 仅在交互动作（`.map-stage-interacting`）或激活态期间按需声明，交互结束后释放显存。
