# 配置文件治理说明

> 适用版本：deployment.config.json schema v1（2026-08）
> 配套代码：`Code/backend/app/services/deployment_config.py`、`app/api/config_routes.py`（`/config/deployment*`）、前端 `src/views/DeploymentConfigView.vue`（路由 `/deployment`，仅 admin）
> 本文是配置文件的**单一真源说明**：谁可改、如何加载、如何保存、如何重载、坏了怎么恢复。

---

## 1. 配置分层模型

系统配置分四层，各层修改入口与生效方式不同：

| 层 | 内容 | 存储 | 生效方式 |
|---|------|------|---------|
| **部署/数据配置** | 数据盘根、运行时目录、缓存、导入配额、Docker/Open-Meteo 键 | `deployment.config.json`（真源）+ `.env`（镜像） | 重启后端进程组（docker 组键需全量重启） |
| **底层引导配置** | 鉴权密钥、GEE 加密主密钥、CORS、worker 数等 | `Code/backend/.env` | 重启后端进程组 |
| **运行时热载配置** | API Key、GEE 账号、天气 Provider、远程存储凭据 | SQLite（DB overlay） | `invalidate_effective_config` 热载，无需重启 |
| **用户偏好** | 界面外观、面板布局、tab 记忆 | 浏览器 localStorage（`settings-local`） | 即时，仅本浏览器 |

**优先级**（同一键多处出现时，后者覆盖前者）：

```
默认值 < .env < deployment.config.json（启动时逐键覆盖 os.environ）
```

DB overlay（api_keys / runtime_config 投影）在 `Settings()` 实例化后由 `hydrate_effective_config()` 叠加，属运行时热载层，不参与文件优先级。

## 3. deployment.config.json（schema v1）

### 3.1 键位映射

真源键 → 环境变量 → 生效方式（`restart-backend` = `launch.py restart backend`；`restart-full` = `launch.py restart` 全量）：

| 组 | 键 | 环境变量 | 类型 | 生效方式 | 约束 |
|---|---|---|---|---|---|
| data | `data_root` | `BACKEND_DATA_ROOT` | path | restart-backend | **目录必须已存在** |
| data | `output_root` | `BACKEND_OUTPUT_ROOT` | path | restart-backend | **目录必须已存在**；留空且 `data_root` 变更时**联动派生** `<data_root>/ProjectOutput`（自动创建，仅写 .env 镜像，不写入 json；显式设置优先） |
| data | `project_backup_root` | `BACKEND_PROJECTBACKUP_ROOT` | path | restart-backend | — |
| runtime | `runtime_root` | `BACKEND_RUNTIME_ROOT` | path | restart-backend | 未设时派生 `<data_root>/_runtime` |
| runtime | `workflow_state_dir` | `BACKEND_WORKFLOW_STATE_DIR` | path | restart-backend | — |
| runtime | `log_dir` | `BACKEND_LOG_DIR` | path | restart-backend | — |
| runtime | `log_level` | `BACKEND_LOG_LEVEL` | level | restart-backend | DEBUG/INFO/WARNING/ERROR |
| runtime | `result_artifact_dir` | `BACKEND_RESULT_ARTIFACT_DIR` | path | restart-backend | — |
| runtime | `python_provider_workspace` | `BACKEND_PYTHON_PROVIDER_WORKSPACE` | path | restart-backend | — |
| runtime | `spatialite_db_path` | `BACKEND_SPATIALITE_DB_PATH` | path_file | restart-backend | 文件路径 |
| caches | `cache_dir` | `BACKEND_CACHE_DIR` | path | restart-backend | 不存在保存时自动创建 |
| caches | `static_cache_root` | `BACKEND_STATIC_CACHE_ROOT` | path | restart-backend | 同上 |
| caches | `static_cache_ttl_seconds` | `BACKEND_STATIC_CACHE_TTL_SECONDS` | int | restart-backend | ≥0 |
| caches | `download_source_root` | `BACKEND_DOWNLOAD_SOURCE_ROOT` | path | restart-backend | 真实数据保存与下载位置 |
| caches | `cache_default_ttl_seconds` | `BACKEND_CACHE_DEFAULT_TTL_SECONDS` | int | restart-backend | ≥0 |
| caches | `tile_proxy_cache_ttl_seconds` | `BACKEND_TILE_PROXY_CACHE_TTL_SECONDS` | int | restart-backend | ≥0 |
| imports | `max_imports_total_bytes` | `BACKEND_MAX_IMPORTS_TOTAL_BYTES` | int | restart-backend | ≥1 |
| imports | `imports_soft_reserve_bytes` | `BACKEND_IMPORTS_SOFT_RESERVE_BYTES` | int | restart-backend | ≥0（0=禁用） |
| docker | `minio_root_user` | `MINIO_ROOT_USER` | str | **restart-full** | compose 注入 |
| docker | `minio_root_password` | `MINIO_ROOT_PASSWORD` | password | **restart-full** | 全链路脱敏；留空=不改 |
| docker | `open_meteo_host_port` | `OPEN_METEO_HOST_PORT` | int | **restart-full** | 1–65535 |
| docker | `open_meteo_data_volume` | `OPEN_METEO_DATA_VOLUME` | str | **restart-full** | 双写 data-sync/.env |
| docker | `open_meteo_sync_domains` | `OPEN_METEO_SYNC_DOMAINS` | str | restart-backend | 双写 data-sync/.env（`visibility` 需 `gfs_global`） |
| docker | `open_meteo_sync_variables` | `OPEN_METEO_SYNC_VARIABLES` | str | restart-backend | 双写 data-sync/.env |
| docker | `open_meteo_local_url` | `BACKEND_OPEN_METEO_LOCAL_URL` | url | restart-backend | redis 并发判定按此 host:port 匹配 |

- 空字符串 / null / 缺键 = **未设置，不覆盖**。
- `notes` 字段：部署说明（数据盘挂载点、机构名等），随文件保存。
- `schema_version`：当前 1；loader 拒绝未知版本（fail-closed），升级走新版本号 + 迁移函数。
- 文件路径可经 `BACKEND_DEPLOYMENT_CONFIG` env 改址（自举场景）。

### 3.2 加载链（启动时）

```
① load_dotenv(Code/backend/.env)                  # 不变
② deployment.config.json 存在 → 解析 + schema 校验
   → 逐键 os.environ 覆盖（优先于 .env）
   → 解析/校验失败 → 拒启（fail-closed，错误含 .bak 恢复指引）
③ Settings() 冻结实例化
```

FastAPI / Celery worker / Beat 均经 `import app.core.config` 触发同一加载链，覆盖自动生效；`launch.py` 不消费这些键，无需改动。

## 4. 生命周期矩阵（修改 → 校验 → 保存 → 重载）

| 变更对象 | 修改入口 | 校验 | 保存 | 生效/重载 |
|---|---|---|---|---|
| deployment.json 全部键 | 配置中心 `/deployment`（admin） | 预览全量校验（绝对路径/存在性/端口范围/TTL 下限/schema），服务端 PUT 前重新校验 | 原子应用（§5） | restart-backend 键：UI 内一键重启；restart-full 键：服务器执行 `launch.py restart` |
| 旧入口 `PUT /config/data-source/paths` | 设置 → 数据源 | 既有路径校验 | 写 `.env` | 重启后端（保留兼容，勿新增依赖；页面已有引导至配置中心） |
| 凭据 / Provider（DB） | 既有设置面板 | 既有 | DB | `invalidate_effective_config` 热载 |
| `.env` 手改（运维应急） | 文件系统 | 启动断言 | — | 重启后生效；与 deployment.json 冲突时**后者优先**（启动日志打印覆盖键清单） |
| 前端偏好 | 界面设置 | — | localStorage | 即时 |

## 5. 原子应用序列与恢复（runbook）

保存（PUT）在服务端按序执行，任一步失败整体回滚，**拒绝半应用状态**：

```
1. 备份轮换：.bak.2→.bak.3、.bak.1→.bak.2、当前→.bak.1（保留 3 份）
2. upsert_env_keys() 写 Code/backend/.env（全部映射键；密码类仅非空才写）
3. 含 docker.open_meteo_* 同步键 → upsert 到 Code/infra/data-sync/.env
4. 临时文件 + os.replace 原子写 deployment.config.json
5. 任一步失败：按第 1 步前读到的旧字节反向恢复 .env 与 json
```

### 5.1 恢复场景

| 症状 | 处置 |
|---|---|
| 后端拒启，报 deployment.config.json 解析/schema 失败 | 错误信息含文件路径与 `.bak.1` 位置：`copy deployment.config.json.bak.1 deployment.config.json` 后重启；或经 `/deployment` 页面重新保存正确配置 |
| 保存后行为异常（路径错） | `/deployment` 改回正确值重新保存（自动再轮换备份），或用 `.bak.2/.bak.3` 手工回退 |
| data-sync/.env 双写失败 | PUT 整体回滚，无残留；排查 `Code/infra/data-sync` 目录权限后重试 |
| 端口改后 Open-Meteo 不可达 | 确认 `open_meteo_host_port` 与 `open_meteo_local_url` 一致；redis 并发判定按 `open_meteo_local_url` 的 host:port 匹配，改端口不再失效 |

### 5.2 部署机初始化流程

1. 按实验室数据盘模板（`Docs/03-规范协议/当前数据源与产出一览.md`）建立目录结构（任意盘符/挂载点）；
2. 复制 `Code/backend/.env.example` → `.env`，按顶部「部署机必改清单」逐项确认；
3. admin 登录前端 → `/deployment` → 填 `data_root`/`output_root` 等 → 预览 → 确认保存 → 按提示重启；
4. `GET /config/deployment` 验证三方一致（运行值 = .env = json）；
5. `GET /layers` 确认 `run_readiness` 按新根变化。

## 6. 漂移检测

`GET /config/deployment` 对每个键返回三方对比：`runtime_value`（当前进程）/ `env_value`（.env）/ `config_value`（json 真源）+ `source`。任一 `pending` 键 → 顶层 `pending_restart=true`，前端显示「待重启生效」徽章。`.env` 手改不更新 json 时即被此机制暴露。
