# 第一部分 · 部署

## 1. 部署形态：先选一个

启动器 `launch.py` 有三种形态，**默认 `bare`**。三者**端口互斥**，切换前必须先 `stop`。

| 形态 | 命令 | 应用层跑在哪 | 适用场景 | 前端更新方式 |
|---|---|---|---|---|
| **bare**（默认） | `launch.py start` | 本机 `Env/Python312` 进程 | 开发机日常联调、裸机长期运行 | 需 `npm run build` 刷新 `dist` |
| **dev** | `launch.py start --mode dev` | 同 bare | 前端高频改码（HMR 改完即刷新） | Vite HMR，自动生效 |
| **prod** | `launch.py start --mode prod` | Docker 容器（`cgda-backend` / `cgda-web`） | 交付 / 生产 | 需重新构建镜像 |

三种形态**共用同一套基础设施容器**（Redis / MinIO / Open-Meteo），所以不要同时起
bare 和 prod——后端同为 8000、网关同为 5175，会抢端口。

> 形态常量定义见 `launch/constants.py` 的 `MODE_BARE/MODE_DEV/MODE_PROD`。
> 交付态的镜像与编排细节见 `部署手册与硬约束清单.md` §12。

## 2. 前置条件

### 2.1 软件

| 软件 | 版本要求 | 核对命令 |
|---|---|---|
| Python | **3.12**（必须是仓库内 `Env/Python312`） | `Env\Python312\python.exe -V` |
| Node.js | 22（CI 亦用 22） | `node -v` |
| Docker Desktop | 任意近期版 | `docker info` |
| Git | 任意近期版 | `git -v` |

**Python 是硬约定**：后端 / Worker / pytest / `launch.py` 全都必须用 `Env/Python312`。
用系统 `python` 会出现依赖版本不一致的"环境幽灵问题"。`launch.py` 检测到当前不是
`Env/Python312` 时会自动 re-exec 切换（见 `launch/env_python.py`）。

### 2.2 Windows 专属：Docker 必须管理员身份

在 Windows 上，**Docker Desktop 与执行启动命令的终端都要以管理员身份运行**，否则
常见失败表现：

- `launch.py start` 报「Docker 未运行或未安装」
- 镜像拉取失败 / named volume 访问失败
- `docker compose up` 服务起不全

排障顺序：退出 Docker Desktop → 右键「以管理员身份运行」→ 等托盘图标稳定
→ 管理员终端执行 `docker info` 确认无报错 → 再 `launch.py start`。

Linux / macOS 只需保证 Docker 守护进程在跑，无此要求。

### 2.3 端口契约（改端口前先看这张表）

| 服务 | 宿主机端口 | 容器内 | 说明 |
|---|---|---|---|
| FastAPI 后端 | **8000** | — | `BACKEND_PORT`，文档在 `/docs` |
| Nginx 网关（前端入口） | **5175** | 80 | 静态 `dist` + 反代 API |
| Vite（`--mode dev` / `--vite`） | 5174 | — | 被网关反代，**对外仍是 5175** |
| Redis | **16379** | 6379 | **不是 6379**，见下 |
| MinIO API / Console | 9100 / 9101 | 9000 / 9001 | 默认 `minioadmin/minioadmin` |
| Open-Meteo API | 8080 | 8080 | 数据在 named volume |

> **为什么 Redis 是 16379**：Windows Hyper-V / WinNAT 会动态保留一段端口（本机常见
> 6326–6425，正好含 6379），绑定会报
> `An attempt was made to access a socket in a way forbidden by its access permissions`。
> 该报错**与是否管理员无关**。查看保留段：`netsh interface ipv4 show excludedportrange protocol=tcp`。
> MinIO 改 9100/9101 同理。
>
> 注意 CI（`.github/workflows/ci.yml`）用的是标准 6379，本地与 CI 的
> `BACKEND_REDIS_URL` 不同，这是**有意为之**，不要"顺手统一"。

## 3. 首次部署 SOP（全新机器）

全程在**仓库根**执行。预计 40–90 分钟（主要是依赖安装与数据同步）。

### S0 拉取代码

```bash
git clone https://github.com/li589/WebGIS.git
cd WebGIS
git checkout dev          # 开发用 dev；部署发布版本用 main
```

### S1 建 Python 运行时

`Env/` 目录**不入库**，必须自建：

```bash
# Windows
python -m venv Env\Python312
Env\Python312\Scripts\python.exe -m pip install --upgrade pip

# Linux / macOS
python3.12 -m venv Env/Python312
Env/Python312/bin/python -m pip install --upgrade pip
```

安装依赖（注意顺序：先运行时，再开发工具）：

```bash
Env\Python312\python.exe -m pip install -r Code/backend/requirements.txt
Env\Python312\python.exe -m pip install -r Code/backend/requirements-dev.txt
```

> 依赖已按版本锁定（供应链加固）。升级请**显式改 requirements 文件**，不要用
> `pip install --upgrade` 就地漂移。
>
> 科学栈（rasterio / netCDF4 / h5py / pandas 等）在 Windows 上若编译失败，
> 优先找预编译 wheel；实在装不上再考虑用 `Env/Python312` 同版本的 conda 方案。
>
> `test_archive_safe.py` 需要 `Code/backend/vendor/unrar/win-x64/UnRAR.exe`
> （gitignore，从 rarlab 下 `unrarw64.exe -s -d` 解出）；Linux 可用 `apt install unrar`。
> **不影响主流程**，只影响该测试。

### S2 装前端依赖

```bash
cd Code/frontend
npm ci --prefer-offline
cd ../..
```

用 `npm ci`（严格按 lockfile）而非 `npm install`，避免依赖漂移。

### S3 配置 `.env`

```bash
copy Code\backend\.env.example Code\backend\.env      # Windows
# cp Code/backend/.env.example Code/backend/.env       # Linux/macOS
```

**至少**要改这几项（其余保持默认即可启动）：

| 键 | 必改原因 |
|---|---|
| `BACKEND_ADMIN_PASSWORD` | 默认开发口令已废弃；**仅首次播种生效**，见下 |
| `BACKEND_API_KEY` | 服务密钥，留空会回退到已知开发默认 key |
| `BACKEND_DATA_ROOT` | 地理数据根。production 下为空会**拒启** |
| `BACKEND_OUTPUT_ROOT` | 产物输出根 |
| `BACKEND_GEE_CREDENTIALS_ENCRYPTION_KEY` | 64 hex chars；非 development 缺 key **拒启** |

生成强随机值：

```bash
Env\Python312\python.exe -c "import secrets; print('password:', secrets.token_urlsafe(24))"
Env\Python312\python.exe -c "import secrets; print('apikey  :', secrets.token_hex(32))"
Env\Python312\python.exe -c "import secrets; print('enckey  :', secrets.token_hex(32))"
```

> **两个反复踩过的坑**：
> 1. `BACKEND_ADMIN_PASSWORD` **只在库里没有用户时播种一次**。已有账号后改它
>    **完全无效**——要改运行期口令必须走
>    `Code/backend/scripts/rotate_user_passwords.py`（见 [§9.4](#94-凭据轮换)）。
> 2. 改口令**不会吊销已存在的会话**。轮换脚本默认会吊销，漏了用
>    `revoke-sessions --all` 补救。

### S4 起基础设施

```bash
Env\Python312\python.exe launch.py start docker
```

会起三个容器：`cgda-redis`、`cgda-minio`（+ `cgda-minio-init` 建桶）、`cgda-open-meteo`。

核对：`docker ps` 三个容器 `healthy`；`launch.py status` 显示 Redis 可达。

### S5 起全栈

```bash
Env\Python312\python.exe launch.py start          # 裸机态（默认）
# 或
Env\Python312\python.exe launch.py start --mode dev   # 前端 HMR
```

这会启动：Docker 栈 + FastAPI(:8000) + **7 个 Celery Worker** + Beat + Nginx 网关(:5175)。

首次启动会自动 `clean-cache`（清 `__pycache__` 与 Vite 缓存）。

> Worker 是按队列拆的 7 个（realtime / standard / heavy / batch / download / gee / weather），
> 其中 standard 和 heavy 各 2 个进程实例——Windows 下 celery prefork 不可用，
> 用多进程实例实现队列内真并行。可用 `CGDA_WORKER_INSTANCES_<NAME>` 覆盖
> （见 `launch/constants.py` 的 `CELERY_WORKERS`）。

### S6 数据同步（可选但推荐）

Open-Meteo 天气数据落在 named volume，首次需要同步：

```bash
Env\Python312\python.exe launch.py sync
```

耗时较长（GB 级）。不做也能起服务，只是天气图层无数据。

按 [§6 验收清单](#6-验收清单可勾选) 逐项打勾。

## 4. 日常启停与三态（bare/dev/prod）

### 4.1 命令总表

| 命令 | 作用 |
|---|---|
| `start.bat` / `./start.sh` | 启动全部（推荐入口） |
| `Env\Python312\python.exe launch.py start` | 同上 |
| `… launch.py start --mode dev` | 开发态（HMR） |
| `… launch.py start <component>` | 单组件：`docker` / `fastapi` / `beat` / `worker` / `worker:<name>` / `frontend` / `gateway` |
| `… launch.py restart backend` | **只**重启 FastAPI + Workers + Beat（不动 Docker/网关）；**改了 `.env` 就用这个** |
| `… launch.py restart` | 全量重启（含网关）；改前端后加 `--rebuild-frontend` |
| `… launch.py reload gateway` | 仅热重载 Nginx 配置（不重建容器） |
| `… launch.py status` | 服务状态总览 |
| `… launch.py logs [component] [-n N]` | 看日志 |
| `… launch.py stop` | 停全部 |
| `… launch.py clean-cache` | 清 `__pycache__` + Vite 缓存（**不**碰 Redis） |
| `… launch.py flush` | ⚠️ Redis `FLUSHDB` + 删天气文件缓存 |
| `… launch.py sync [job]` | 数据面一次性同步 |

> ⚠️ `flush` 会清空队列、缓存、限流与断路器状态，影响在线服务。
> **`start` / `restart` 永不自动 flush**，只能手动执行。
> 代码没生效时先试 `clean-cache` 或 `restart`，不要一上来就 flush。

### 4.2 缓存分层（"改了没生效"先看这里）

| 层 | 清理方式 | 影响 |
|---|---|---|
| Python 字节码 | `launch.py clean-cache` | 无副作用 |
| Vite 前端缓存 | `launch.py clean-cache` | 无副作用 |
| 前端 `dist` | `restart --rebuild-frontend` | 无副作用 |
| Redis（队列/会话/限流） | `launch.py flush` | ⚠️ 影响在线服务 |
| 天气文件缓存 | `launch.py flush` | 需重新同步/拉取 |

完整边界说明见 `Docs/07-工程保障/联调缓存与生效边界.md`。

## 5. 交付态（prod）与生产切换

### 5.1 交付态启动

```bash
# 1) 在 Code/backend/.env 配好必填项
#    CGDA_TAG=<镜像 tag>
#    CGDA_DATA_ROOT=<宿主数据根>

# 2) 停掉裸机态（端口互斥）
Env\Python312\python.exe launch.py stop

# 3) 起交付栈
Env\Python312\python.exe launch.py start --mode prod
```

`CGDA_TAG` / `CGDA_DATA_ROOT` 缺失时，启动器会**提前报错**，而不是让 compose 抛长串英文。

交付态运维子命令：

```bash
… launch.py deploy config      # 干跑校验（不构建不起栈，先看配置对不对）
… launch.py deploy build       # 只构建镜像
… launch.py deploy up          # 起栈（--no-build 跳过构建）
… launch.py deploy restart     # 重建后 force-recreate
… launch.py deploy ps          # 状态
… launch.py deploy logs [svc] -n N
… launch.py deploy down        # 停栈（--volumes 连卷删，危险）
```

### 5.2 生产/交付必改清单

| # | 项 | 说明 |
|---|---|---|
| 1 | `BACKEND_ENV=production` | 影响 CSP/HSTS、限流生效、fail-closed 策略 |
| 2 | `BACKEND_ADMIN_PASSWORD` | 强随机；且**轮换掉**播种用的口令 |
| 3 | `BACKEND_API_KEY` | 强随机，勿留空 |
| 4 | `BACKEND_API_KEY_ROLE` | 保持 `standard`。设 `admin` 会让这把共享静态密钥拥有完整管理员权限，且使用**无法归因到人** |
| 5 | `BACKEND_GEE_CREDENTIALS_ENCRYPTION_KEY` | 64 hex；非 development 缺 key 拒启 |
| 6 | `BACKEND_DATA_ROOT` / `OUTPUT_ROOT` | production 空根拒启 |
| 7 | `BACKEND_DEV_AUTH_PREFILL=false` | 否则登录页会把口令预填给访问者 |
| 8 | `BACKEND_API_KEYS_ENABLED=true` | 为 false 时 development 下 loopback 可旁路鉴权 |
| 9 | MinIO 凭据 | 覆盖默认 `minioadmin/minioadmin`，与后端 `BACKEND_MINIO_*` 一致 |
| 10 | 演示开关 | **禁止**开 `BACKEND_DEMO_SOURCES_ENABLED` / `BACKEND_NODE_STUBS_VISIBLE` |
| 11 | `BACKEND_CORS_ORIGINS` | 按实际前端域名收窄，**勿用 `*`** |
| 12 | `BACKEND_TRUST_PROXY` | 仅在受信 Nginx 同域入口后设 `true`；直连 FastAPI 时保持 `false` |

完整清单与条款出处见 `部署手册与硬约束清单.md` §6，交付核对见 `delivery-checklist.md`。

### 5.3 `BACKEND_ENV` 怎么选（容易搞混）

`BACKEND_ENV` 影响的是**应用层安全策略**，与 `launch.py --mode`（进程形态）是两件事：

| `BACKEND_ENV` | 表现 |
|---|---|
| `development` | 无 HSTS/CSP；IP 限流**整体旁路**；dev 预填、dev 旁路可用；缺加密 key 仅告警 |
| `production`（默认） | 强制安全头；限流生效；fail-closed：空数据根 / 空用户表 / 缺加密 key 均**拒启** |
| `test` | 测试专用，CI 与 pytest 注入 |

> 注意 `environment` 的默认值已反转为 `production`（fail-secure）——
> **不配就是生产策略**，这不会让开发变麻烦（开发会在 `.env` 显式设为 development），
> 但会让"忘记配"的部署变安全。

## 7. 故障速查索引

| 症状 | 最可能原因 | 处置 |
|---|---|---|
| `launch.py` 报 Docker 未运行 | Windows 未用管理员 | 管理员重开 Docker Desktop + 终端 |
| `bind: … forbidden by its access permissions` | Hyper-V 保留了端口 | 换端口，或 `netsh interface ipv4 show excludedportrange protocol=tcp` 查保留段 |
| 8000 / 5175 起不来 | 裸机态与交付态同时开着 | `launch.py stop` 后切换形态 |
| 改了后端代码没生效 | 字节码缓存 / 进程未重载 | `launch.py restart backend`；仍不行 `clean-cache` |
| 改了 `.env` 没生效 | 需重启进程组 | `launch.py restart backend`（改数据根必须） |
| 改了前端没生效 | 用的是 `dist` 而非 HMR | `--rebuild-frontend` 或改用 `--mode dev` |
| 登录 429「已被临时锁定」 | 账号失败锁定（5 次/15 分钟） | 等 15 分钟，或管理员 `POST /auth/users/{id}/unlock` |
| 改了 `.env` 口令仍能用旧口令登录 | 口令只在空库时播种 | 走 `rotate_user_passwords.py`（[§9.4](#94-凭据轮换)） |
| 生产起不来，日志说拒启 | fail-closed 命中 | 看日志指的具体是数据根 / 加密 key / 用户表 |
| 天气图层空白 | volume 未同步 | `launch.py sync` |
| GEE 功能不可用 | 未配凭据或桥接关闭 | 见 `AGENTS.md` 高风险区 §3 |
| Windows 下工作流只能串行跑 | celery prefork 不可用 | 已用多 worker 实例规避；可加 `CGDA_WORKER_INSTANCES_HEAVY=3` |

更多排障（WinNAT、事故记录）见 `Docs/07-工程保障/运维手册.md`。

## 8. 再开发环境（从零重建）

已按 [§3](#3-首次部署-sop全新机器) 部署过的机器可跳过本节。

```bash
# 1. 运行时
python -m venv Env\Python312
Env\Python312\python.exe -m pip install -r Code/backend/requirements.txt -r Code/backend/requirements-dev.txt

# 2. 前端
cd Code/frontend && npm ci && cd ../..

# 3. 质量门禁（pre-commit，强烈建议）
Env\Python312\python.exe -m pip install pre-commit
Env\Python312\python.exe -m pre-commit install

# 4. 开发态起服务
Env\Python312\python.exe launch.py start --mode dev
```

**开发态（`--mode dev`）是日常改码的首选**：前端走 Vite HMR（:5174，对外仍是 :5175），
改 `.vue` / `.ts` 保存即刷新；后端 FastAPI 在 development 下也带 reload。

### 8.1 必须知道的两条硬约定

1. **Python 只用 `Env/Python312`**。写命令时带上完整路径，别用 `python`。
2. **Windows 提交前先 `git add -A` 全量暂存**。禁止部分暂存 / pathspec 提交
   （`git commit -- <paths>`）——pre-commit 的 stash/restore 在 Windows 文件锁下
   会吞掉未暂存改动（2026-08-16 事故）。丢失可从 `~/.cache/pre-commit/patch<时间戳>`
   用 `git apply` 找回。

### 9.4 凭据轮换

**这是最容易做错、后果最严重的操作**，单独列出。

```bash
cd Code/backend

# 1) 审计：还有哪些账号能用已知口令（exit 3 = 有风险）
Env\Python312\python.exe scripts\rotate_user_passwords.py list --probe <旧口令>

# 2) 轮换（默认会一并吊销会话，--keep-sessions 可关）
Env\Python312\python.exe scripts\rotate_user_passwords.py rotate --all --probe <旧口令>

# 3) 复核为 exit 0
Env\Python312\python.exe scripts\rotate_user_passwords.py list --probe <旧口令>

# 4) 万一漏了吊销
Env\Python312\python.exe scripts\rotate_user_passwords.py revoke-sessions --all
```

**为什么必须这样**：改 `.env` 只影响"空库播种"，对已存在账号**完全无效**；
且直接改 `password_hash` 不会吊销既有会话——攻击者在轮换前建立的会话依然有效。
这两条都曾被误当成"已修复"，务必按脚本走完整闭环。

## 11. 常见扩展任务的标准做法

### 11.1 新增后端 API

1. 在 `app/api/routers/` 下按域新增或扩展 router
2. 在 `app/api/routers/__init__.py` 注册
3. **需要写权限就挂依赖**：`require_session` / `require_admin` / `require_write_access`
   （见 `app/api/deps.py`）——不要自己写鉴权判断
4. 业务异常用 `ApiError(spec, status_code=..., detail=...)`，保持
   `{detail, error_code, request_id}` 响应口径（`app/api/error_codes.py`）
5. 若改动响应结构，同步 `Code/frontend/openapi.json` 并跑 `npm run check:openapi`

### 11.2 新增算法模块

1. 在 `Code/algorithms/providers/Python/modules/` 下新增
2. 用 `template_overrides={"phase": ...}` 声明阶段
3. 阶段分类逻辑在 `backend/services/python_provider_bridge_service.py::_classify_stage`
4. 跑 `pre-commit run --all-files`（ruff + mypy 覆盖 `algorithms/`）
5. 阶段分类测试：`Test/backend/test_module_phase_classification.py`

### 11.3 新增图层

1. 后端：`catalog_seeds/*_descriptors.json`
2. 前端：`Code/frontend/src/.../catalog.ts` 的 `LAYER_LIBRARY`
3. 两侧必须一致 —— 用 `npm run check:catalog` 查漂移
4. 命名规范见 `Docs/03-规范协议/layer-naming.md`

### 11.4 新增前端视图

1. `src/views/` 加视图，`src/router.ts` 注册路由
2. 状态放 `src/stores/`；**用 `toRef(store, key)` 逐字段引用**
   （Vue 3.5.38 + Pinia 3.0.4 下 `storeToRefs` 对 undefined 属性有缺陷）
3. 测试放 `Test/frontend/`（保留 `src/` 目录结构，相对导入改写为 `@/`）
4. 跑 `npm run test && npm run lint && npm run build`

### 11.5 改口令 / 安全策略相关

口令策略已下沉到存储层（`app/services/passwords.py::validate_password`），
`UserRepository.create_user` / `update_user` 强制校验：**≥8 位 + ≥2 类字符 +
不在弱口令黑名单 + 不含用户名**。

> ⚠️ 改这条策略会**反噬测试夹具**：`test_themes.py` / `test_auth.py` 曾因
> `password123`（黑名单）和 `Std1-Pw-9a7!`（含用户名 std1）被拦下。
> 改策略后务必同步搜一遍测试口令。

## 13. 避坑清单（按踩坑频率排序）

### 13.1 本机特有（Windows + AI 沙箱）

| 坑 | 表现 | 规避 |
|---|---|---|
| **WorkBuddy safe-delete shim** | pytest 里含文件删除的用例**假阳性失败**（`windows-sandbox-recycle-bin-unavailable`） | 用前缀禁用 shim：`CODEBUDDY_SESSION_ID= CLAUDE_SESSION_ID= CODEBUDDY_SAFE_DELETE_SANDBOX= Env/Python312/python.exe -m pytest Test/backend -p no:cacheprovider --basetemp="Test/.pytest-be"` |
| **沙箱会回收子进程** | 从 AI 工具里起后端，工具调用一结束进程就没了 | 后端在**自己的终端**里启动，不要用 AI 工具的 Bash 起长驻进程 |
| **uvicorn 未必重载到最新代码** | 改了 `main.py` 这类启动期文件，curl 实探测却还是旧行为 | 判断"是否生效"以 TestClient 用例为准，或显式 `launch.py restart backend`，别只信 curl |
| **Docker 需管理员** | 见 [§2.2](#22-windows-专属docker-必须管理员身份) | 管理员身份 |
| **Hyper-V 保留端口** | `bind: forbidden` | 见 [§2.3](#23-端口契约改端口前先看这张表) |

### 13.2 架构与语义

| 坑 | 说明 |
|---|---|
| `.env` 口令只播种一次 | 改运行期口令走 `rotate_user_passwords.py` |
| 改口令不吊销会话 | 轮换脚本默认吊销；漏了用 `revoke-sessions --all` |
| `flush` 会清队列 | 只在排障时用；`start`/`restart` 永不自动执行 |
| `deployment.config.json` 是真源 | 加载链 `json → .env 覆盖 → Settings()`；文件损坏 **fail-closed 拒启**，错误里有 `.bak.1/.2/.3` 恢复指引 |
| 改数据根后要重启 | `launch.py restart backend`，再 `GET /layers` 看 `run_readiness` |
| 后端主叙事是 `workflow-runs` | 旧 `/tasks` 仅兼容桥接，**勿新增依赖** |
| 加密主密钥是共享爆炸半径 | 同一把 key 加密 GEE SA / API keys / 天气源 / 远程存储 / 门户凭据 |
| 裸机态与交付态端口互斥 | 切换前 `launch.py stop` |

### 13.3 鉴权相关

| 坑 | 说明 |
|---|---|
| `BACKEND_API_KEY_ROLE` 非 `admin` 的值曾被**静默**降级为 standard | 现已白名单化（`admin`/`standard`/`demo`），未知值打 ERROR |
| `LOOPBACK_IPS` 曾含永不命中的 `"localhost"` | 判定改走 `is_loopback_host()`（支持主机名、`::ffff:` 映射、`127.0.0.0/8`） |
| 账号锁定对所有用户名生效 | 这是**有意为之**：否则"锁定=账号存在"会成为用户名枚举预言机。代价是可被恶意连错做 DoS，用 `POST /auth/users/{id}/unlock` 缓解 |
| 主题 logo 允许 SVG | 上传拦截脚本载体 + 下发强制 CSP sandbox；不要放宽这两层 |
