## 4. 再开发闭环与分支规范

```
远端编辑代码 (codegraph)  →  git commit  →  git push origin dev  →  本地 git pull 校验
```

### 分支策略（对应 `部署与再开发指南.md` §12）

- **远端只推 `dev`**（日常开发分支）。
- **`main` 只做阶段性发布合并**，标准流程：

```bash
git checkout dev && git add <路径> && git commit -m "type: ..."
git push origin dev

git checkout main
git pull --ff-only origin main
git merge dev --no-edit          # 无冲突自动合并
git push origin main
git checkout dev
```

> **关于"无冲突自动合并也行吗"**：可以。只要 `main` 只接受来自 `dev` 的合并，
> `git merge dev` 就**不会产生冲突**（多数情况直接快进）。
> 若想让每次阶段发布在历史上留一个**可见的合并点**，把命令换成 `git merge dev --no-ff --no-edit`。
> 两种都安全，差别只是 `main` 的图形是否线性。

### 纪律

- **严禁 `git add -A` / `git commit -a`** ——远端历史上那 667 条删除就是没复制 `Test/` 造成的，
  全量 add 会把 `Test/`、`Docs/` 的删除写进历史。
- 提交信息用 Conventional Commits（pre-commit 的 `conventional-pre-commit` 强制）。

## 5. 风险登记

| 风险 | 说明 | 处置 |
|---|---|---|
| 误删跟踪文件 | `git add -A` 会把 `Test/` 609 个文件的删除写入历史 | 禁止；P1 先复原 |
| 凭据暴露 | `.env` 含 `cgda-dev-admin`，公网隧道已上线 | 开发阶段接受（主人决策）；交付前必轮换 |
| 隧道 token | 可运行该隧道的凭据 | **不入库**，只存在于远端服务配置 |
| E 盘余量 | 全量 761 GB 后仅余约 365 GB | 按需分批，`ProjectOutput` 可考虑落 F 盘 |
| A1 防火墙窗口 | 临时放行 445 | 限源 IP + 用完立即撤销 |
| Cloudflare 上传上限 | 单次 100 MB、长连接波动 | 大文件走 A1（LAN），不走隧道 |
