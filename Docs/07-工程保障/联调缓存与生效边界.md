# 联调缓存与生效边界

> 活文档：说明 CGDA 本地联调中**各层缓存的职责、自动清理时机、排障顺序**。  
> 实现：`launch/cache_hygiene.py`；Gateway 契约见 `Code/infra/gateway/nginx.conf`。

## 分层一览

```text
浏览器缓存
  └─ index.html（须 no-store）→ 指向 hashed chunks
Nginx Gateway :5175
  ├─ 静态剖面：dist/ + /assets 真 404（禁止缺文件回退 SPA）
  └─ HMR 剖面：反代本机 Vite :5174（WS 同域）
Vite 开发缓存（node_modules/.vite）
Python 进程内存 + __pycache__
Redis / 天气文件缓存（仅 flush，高风险）
```

| 层 | 何时算「生效」 | 默认谁清理 |
|----|----------------|------------|
| 浏览器入口 HTML | 拿到新 `index.html` | Nginx `Cache-Control: no-store` |
| 前端 hashed `/assets/*` | 新 hash 文件存在 | rebuild dist；缺旧 hash → **404** |
| Vite HMR | `--vite` 下改源码即时 | `start`/`restart --vite` 自动清 `.vite` |
| Python 代码 | **新进程**加载模块 | `start`/`restart` backend 等自动清 `__pycache__` |
| Redis / 天气文件 | `flush` 之后 | **永不**由 start/restart 自动执行 |

## 命令对照（勿混用）

| 命令 | 清什么 | 不清什么 | 典型场景 |
|------|--------|----------|----------|
| `launch.py start` / `restart` | 按组件矩阵：pycache 和/或 Vite `.vite` | Redis、天气文件、dist | 日常启停（默认） |
| `… --no-clean-cache` | 跳过上述自动清理 | — | 冷启动要极速、确信缓存干净 |
| `… --clean-cache` | **强制** pycache + Vite 全清 | Redis | 导入怪错 / 插件状态脏 |
| `launch.py clean-cache` | 手动同左 | Redis | 不重启、只清本地编译缓存 |
| `launch.py flush` | Redis DB + 天气文件缓存 | pycache、dist | **仅**排障/强制刷天气缓存 |
| `launch.py reload gateway` | Nginx 配置热重载 | 一切业务缓存 | 改 `nginx.conf` / 维护开关 |
| `launch.py restart backend` | pycache + 换代进程 | Docker / Gateway | 改 `.py` / 数据根后 |
| `start --vite` | Vite 缓存；入口仍 `:5175` | 不必 rebuild dist | 前端开发热更新 |
| `start gateway --rebuild-frontend` | 强制 `npm run build` | — | 静态剖面要更新 dist |

### 自动 clean 矩阵（`launch/cache_hygiene.should_prepare_caches`）

- `all` / `backend` / `fastapi` / `beat` / `worker*` → `__pycache__`
- `frontend` 或 `--vite`（含 `gateway --vite`）→ Vite `.vite`；`all --vite` → 两者
- 仅 `docker` / 静态 `gateway` → 默认不清理
- `restart gateway` 从 HMR 切回静态 → 清 Vite（去掉背后残留态）
- `--no-clean-cache` → 全跳过；`--clean-cache` → 强制两者

`stop` / `stop gateway`：**不**删缓存；只停进程/容器，日志会注明「未执行 flush/clean-cache」。

## 症状 → 动作

| 症状 | 更可能的层 | 动作 |
|------|------------|------|
| `Failed to fetch dynamically imported module: …/SettingsPanel-旧hash.js` | 浏览器仍握旧入口 / 缺 chunk | 硬刷；确认 `/` 为 `no-store`；静态剖面 `npm run build` 或 `--rebuild-frontend`；FE 有一次自动 reload 兜底 |
| 新 API 路由 404，代码已合并 | **旧 FastAPI/Worker 进程** | `restart backend`（勿先 flush） |
| 改 `.py`「没生效」 | 进程未换代或 pycache 脏 | `restart backend`（默认已清 pycache） |
| 改 Vue「Gateway 下不变」 | 静态 dist 未重建 | `--vite` 开发，或 rebuild dist + 硬刷 |
| 模块导入诡异 / Vite 插件异常 | 本地编译缓存 | `clean-cache` 或 `restart --clean-cache` |
| 天气瓦片/队列「怎么清都不对」 | 业务缓存 | 确认后再 `flush`（高风险） |
| 改 nginx 不生效 | 配置未 reload | `reload gateway` |

## Gateway 静态剖面契约

- `GET /` / `index.html`：`Cache-Control: no-store`
- `GET /assets/*`：有 hash 可 `immutable`；**文件不存在必须 404**，禁止 `try_files` 回退成 `index.html`（否则动态 import 把 HTML 当 JS）
- 前端：`src/utils/lazy-chunk.ts` 对 stale chunk 最多硬刷新一次

## 固定排障顺序

1. 看 `launch.py status`（剖面：静态 Gateway / Gateway+HMR / 直连 Vite；缓存约定提示）。
2. 前端怪：是否在 `--vite`？→ Network 看 `index.html` 的 Cache-Control 与 chunk 状态码（404 vs 200 HTML）→ 再决定 rebuild 或硬刷。
3. 后端怪：进程 PID / 启动时间是否换代 → `restart backend` → 仅导入异常再加 `--clean-cache`。
4. **最后**才考虑 `flush`（会清空队列与限流状态）。
