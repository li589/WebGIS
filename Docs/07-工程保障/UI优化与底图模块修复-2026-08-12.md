## 任务 2：底图模块审计与修复

**文件**：`Code/frontend/src/components/map/basemap-module.ts`

### 审计发现问题

| 问题 | 严重度 | 状态 |
|------|--------|------|
| 熔断后无自动恢复机制，必须用户手动重试 | 中 | 已修复 |
| dispose() 未清理 autoRecoveryTimer（新发现）| 低 | 已修复 |
| dispose() 未清空 tileErrorTimestamps 数组 | 低 | 已修复 |
| map.on('error') 使用匿名函数无法显式 off | 低 | 保留（依赖 map.remove() 清理）|

### 修复内容

1. **新增自动恢复机制**：
   - 常量 `AUTO_RECOVERY_DELAY_MS = 15000`（15秒）
   - 新增 `isCircuitBroken` 状态标记
   - 新增 `autoRecoveryTimer` 定时器
   - 熔断触发后 15 秒自动调用 `retryTileLoad()`
   - 切换底图或手动重试时清除定时器

2. **完善资源清理**：
   - `resetTileErrorState()` 中清除自动恢复定时器
   - `dispose()` 中清除 autoRecoveryTimer
   - `dispose()` 中清空 tileErrorTimestamps 数组
   - `dispose()` 中重置 isCircuitBroken 标记

3. **熔断器工作流程**：
   ```
   5秒窗口内错误 > 15次 → 触发熔断
     ↓
   隐藏底图 + 显示错误横幅 + 启动15秒定时器
     ↓
   15秒后自动重试 / 用户手动点击重试 / 用户切换底图
     ↓
   重置错误状态 → 恢复底图显示
   ```

## 任务 6：天地图街道底图（vec + cva）与服务端 UA

**问题**：
1. 街道底图曾误绑 `tianditu-cva`（纯注记），表现为「只有文字没有底图」。
2. 后端代理用 Mozilla UA 拉天地图时，服务端 Key 返回 **403 / 301013**；缓存中残存的 cva 瓦片仍可能显示，加重「只有注记」观感。

**正确设计**：
- 底图源：`tianditu-vec`（矢量底）
- 注记叠层：`tianditu-cva`，经 `overlayUrl` / `overlayUrlTemplate` 由 `basemap-module` 双 raster 叠加
- 遗留 id：`normalizeTileSourceId('tianditu-cva')` → `tianditu-vec`

**后端**（`app/services/tile_proxy_service.py`）：
- `TIANDITU_SERVER_USER_AGENT = "CGDA-Backend/1.0"`
- 仅对 `TileProvider.TIANDITU` 请求附加该 UA（勿再用浏览器 UA）
- Key 连通性测试与拉瓦片 UA 对齐

**验证**：`GET /unified-tiles/tianditu-vec/...` 与 `tianditu-cva/...` 均应 **200**（需有效天地图 Key）。

## 设计一致性说明

所有 UI 修改遵循设计系统规范：

1. **字号**：所有文本 ≥ 12px，caption 使用 12px，body 使用 14px
2. **颜色**：优先使用 CSS 变量（--accent、--danger、--text-* 等），非 scoped 样式因 Teleport 限制使用硬编码但色值与 token 对齐
3. **圆角**：统一使用 --radius-* 变量
4. **玻璃态**：backdrop-filter: blur() 统一风格
5. **动画**：所有动画都有 prefers-reduced-motion 兜底
6. **交互**：按钮 hover 有视觉反馈，active 有下沉效果
7. **Badge**：错误数使用 danger 色，99+ 截断
