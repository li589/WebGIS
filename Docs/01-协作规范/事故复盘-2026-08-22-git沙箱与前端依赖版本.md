## 事故一：git stash 触发 .git 损伤（第二次发生）

**根因**：AI 工具沙箱的 safe-delete shim 拦截涉及批量删除的 git 子操作。`git stash`
内部要做 refs 移动 + 工作区文件替换，被沙箱中途杀死，留下 `.git/refs` 目录被清、
pack 文件只剩 `.idx` 没有 `.pack` 的残局。与 2026-08-21 的 checkout 事故同源。

**恢复**（全程未动工作区文件）：
```
git fetch origin dev                    # SSH 443 通道拉回对象
git update-ref refs/heads/dev <sha>     # 重建 dev 指针
git update-ref refs/remotes/origin/dev <sha>
git reset --mixed                       # 重建 index
```

**规范沉淀**（`.ai/rules/git-safety.md`）：沙箱内禁 stash / checkout 切分支 /
merge / reset --hard；小步提交 + 即时推送；文件级"回退"只允许
`git show <sha>:<path> > <path>`。

## 事故二：storeToRefs undefined.effect 渲染崩溃

**现象**：刷新页面即报 `Cannot read properties of undefined (reading 'effect')`，
ErrorBoundary 捕获，整页不可用。二分注释确认炸点在 `useLayerWorkspace()`
内部；逐字段 `toRef(store, key)` 试验 13 个字段全部成功，而
`storeToRefs(store)` 整体调用抛错。

**根因**（dist `vendor-framework-*.js` 第 85355 行实证）：
Pinia 3.0.4 的 `storeToRefs` 实现遍历 store 的 raw form 每个属性并访问
`t[r].effect`（用于区分 computed）——当 store 上存在 **undefined 值属性**时，
`t[r]` 为 undefined，`undefined.effect` 直接抛 TypeError。
Pinia 2.x 有 undefined 防御，3.0.4 移除了这层保护；Vue 3.5.38 组合下暴露。

**为何长期未发现**：dist 不在 git 中，之前线上跑的是某次旧 build；
首次全量 rebuild（build/type-check 分离那个 commit 之后）才把该路径暴露。

**修复**（commit `d39b2d1`）：`selectors.ts` 三个 composable 内
`storeToRefs` 全部改为 `toRef(store, key)` 逐字段显式包裹（29 字段）。

**规范沉淀**（`.ai/rules/frontend-dependency-compat.md`）：
- vue/pinia 在 package.json 精确 pin（3.5.38 / 3.0.4），禁 `^` 范围；
- 项目内禁用 `storeToRefs`，统一 toRef 逐字段模式；
- dist rebuild 后必须浏览器冒烟。

## 教训清单

1. **沙箱 + git 的批量操作是不可组合的**——stash/checkout/merge 都可能半途被杀，
   且失败是静默的（无输出、留锁文件）。凡涉及删除的 git 操作一律绕行。
2. **工作区滞留的未提交修改是最大风险敞口**——事故中最先丢的就是它们。
   小步提交 + push 是唯一可靠备份。
3. **"用户能跑的 dist" 与 "当前源码 build 的 dist" 可能差好几个 commit**——
   依赖升级、行为变化的坑会在首次 rebuild 时集中爆发。rebuild 必须配冒烟。
4. **框架内部错误要追到 dist 产物里的真实实现**——栈帧名（Wc/T/D）是
   minified 的，grep 产物文件找 `.effect` 这类特征串比猜源码快得多。
5. **诊断探针是负债**——所有 window.__diag / console.error / 注释掉的代码块，
   问题解决后必须立即全部清除，再提交。
